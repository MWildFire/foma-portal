A1.1.1🧠 Компоненты центрального процессораA1.1.1🧠 Components of the central processing unit

Центральный процессор (CPU — Central Processing Unit) — это «двигатель» вычислений всей системы. Именно он выполняет инструкции программ: считает, сравнивает, перемещает данные, управляет всем остальным железом. Внутри CPU есть три большие группы элементов: компоненты (ALU, CU), регистры (быстрые ячейки для текущих данных) и шины (провода, по которым гуляют биты). The central processing unit (CPU) is the "engine" of all computation in the system. It executes program instructions: it calculates, compares, moves data and controls all the other hardware. Inside the CPU there are three main groups of parts: components (ALU, CU), registers (fast cells for current data) and buses (the wires along which bits travel).

➕ Арифметико-логическое устройство (ALU — Arithmetic Logic Unit)➕ Arithmetic logic unit (ALU)

ALU — это место, где реально происходит вычисление. Он умеет складывать, вычитать, умножать, делить, а также выполнять логические операции AND, OR, NOT и сравнения. Когда программа считает 2 + 3 — это работает именно ALU. The ALU is where the calculation actually happens. It can add, subtract, multiply and divide, and it carries out the logical operations AND, OR, NOT and comparisons. When a program calculates 2 + 3, the work is done by the ALU.

🎛️ Устройство управления (CU — Control Unit)🎛️ Control unit (CU)

CU отвечает за оркестрование цикла fetch–decode–execute. Его задачи: The CU is responsible for orchestrating the fetch–decode–execute cycle. Its tasks are:

  • Получать инструкции из памяти.Fetch instructions from memory.
  • Разбирать их (декодировать) — определять opcode (код операции) и операнды.Decode them — identify the opcode (operation code) and the operands.
  • Посылать управляющие сигналы нужным частям CPU: ALU, регистрам, шинам.Send control signals to the parts that need them: the ALU, the registers and the buses.

CU — это «дирижёр»: он не считает сам, но определяет, кто и когда что делает. The CU is the "conductor": it does not calculate itself, but decides who does what and when.

📒 Регистры (Registers)📒 Registers

Регистр — это крошечная, но очень быстрая ячейка памяти внутри CPU. Регистры держат то, что процессор использует прямо сейчас: инструкции, адреса, промежуточные результаты. Пять ключевых регистров, которые надо знать на экзамене: A register is a tiny but very fast storage location inside the CPU. 🚌 Шины (Buses)🚌 Buses

Шина — это общий канал передачи данных между компонентами. Шина — это и физические провода, и протоколы передачи. Три главные шины: A bus is a shared channel for transferring data between components. A bus is both the physical wires and the transfer protocols. The three main buses are:

  • Адресная шина (Address bus) — передаёт адрес ячейки памяти из CPU в контроллер памяти. Однонаправленная: только от CPU. Ширина шины (число проводов) определяет, сколько памяти CPU может адресовать.Address bus — carries a memory address from the CPU to the memory controller. Unidirectional: only from the CPU. The width of the bus (the number of wires) determines how much memory the CPU can address.
  • Шина данных (Data bus) — переносит сами данные и инструкции между CPU и памятью. Двунаправленная: данные могут идти в обе стороны. Её ширина (32 бита, 64 бита) определяет, сколько данных передаётся за одну операцию.Data bus — carries the data and instructions themselves between the CPU and memory. Bidirectional: data can travel in both directions. Its width (32 bits, 64 bits) determines how much data is transferred in one operation.
  • Шина управления (Control bus) — передаёт сигналы управления: read, write, acknowledge, прерывания (interrupts), тактовые сигналы (clock). Может быть односторонней или двусторонней в зависимости от сигнала.Control bus — carries control signals: read, write, acknowledge, interrupts and clock signals. It can be one-way or two-way, depending on the signal.

Все три вместе часто называют системной шиной (system bus).Together, the three are often called the system bus.

Типы процессоровTypes of processors

1️⃣ Одноядерные процессоры (Single-core)1️⃣ Single-core processors

Имеют одно ядро — одну единицу обработки. Выполняют инструкции последовательно, одну за другой. Подходили для ранних компьютеров, но сегодня плохо справляются с многозадачностью и параллельной обработкой — становятся «бутылочным горлышком». They have one core, a single processing unit. They execute instructions sequentially, one after another. They suited early computers, but today they cope poorly with multitasking and parallel processing and become a "bottleneck".

⚙️ Многоядерные процессоры (Multi-core)⚙️ Multi-core processors

Имеют два и более независимых ядра на одном кристалле. Каждое ядро может выполнять свою инструкцию одновременно с другими — это параллельная обработка. Современные CPU могут иметь 4, 8, 16 и больше ядер; серверные — до 128+. They have two or more independent cores on one chip. Each core can execute its own instruction at the same time as the others — this is parallel processing. Modern CPUs can have 4, 8, 16 or more cores; server processors have up to 128 or more.

Это даёт огромный прирост производительности для многозадачности, сложных вычислений и приложений, которые «умеют» использовать параллелизм. This gives a large boost in performance for multitasking, complex calculations and applications that can use parallelism.

🤝 Сопроцессоры (Co-processors)🤝 Co-processors

Это специализированные процессоры, которые «снимают» с главного CPU определённые задачи: рендеринг графики, сложные математические расчёты, шифрование данных. Они освобождают основной CPU для общих задач. Самые известные примеры: These are specialized processors that take certain tasks off the main CPU: graphics rendering, complex mathematical calculations and data encryption. They free the main CPU for general tasks. The best-known examples are:

  • GPU (Graphics Processing Unit) — для графики (см. A1.1.2).GPU (Graphics Processing Unit) — for graphics (see A1.1.2).
  • DSP (Digital Signal Processor) — для обработки сигналов (звук, видео).DSP (Digital Signal Processor) — for signal processing (sound, video).
Параллельная обработка (Parallel processing) — техника, при которой несколько процессоров или ядер одновременно выполняют разные части задачи или разные задачи, чтобы повысить общую скорость и эффективность. Parallel processing — a technique in which several processors or cores simultaneously execute different parts of one task, or different tasks, to increase overall speed and efficiency.
🇬🇧 English summary (click to expand)

The CPU contains three functional groups working together. The ALU (Arithmetic Logic Unit) performs all arithmetic (add, subtract, multiply, divide) and logical operations (AND, OR, NOT, comparisons). The Control Unit (CU) orchestrates the fetch-decode-execute cycle, decoding instructions and issuing control signals. Registers are tiny ultra-fast storage cells: the PC (program counter) holds the address of the next instruction, the IR (instruction register) holds the current instruction, the MAR and MDR interface with memory, and the AC (accumulator) stores intermediate results. Three buses connect components: address bus (unidirectional, CPU to memory), data bus (bidirectional), and control bus (read/write/clock signals). Processors are classified as single-core (sequential execution), multi-core (parallel cores on one die), or co-processors (specialised units like GPUs and DSPs offloading work from the main CPU).

A1.1.2🎮 Роль графического процессора (GPU)A1.1.2🎮 Role of the graphics processing unit (GPU)

Графический процессор (GPU — Graphics Processing Unit) — это специализированный электронный модуль, в котором тысячи маленьких ядер. Например, у Nvidia GeForce RTX 4080 — 9728 ядер. Изначально GPU создавали, чтобы быстро рисовать графику для игр и видео, но сегодня GPU активно используются и для машинного обучения, научных симуляций, обработки больших данных. The graphics processing unit (GPU) is a specialized electronic module with thousands of small cores. For example, the Nvidia GeForce RTX 4080 has 9728 cores. GPUs were originally created to draw graphics quickly for games and video, but today they are also widely used for machine learning, scientific simulations and big data processing.

GPU может быть встроенным (integrated) — частью CPU, или дискретным (discrete) — отдельной картой. С софтом GPU общается через API: DirectX и OpenGL (а в современных проектах также Vulkan, Metal, CUDA). A GPU can be integrated (part of the CPU) or discrete (a separate card). Software communicates with the GPU through APIs: DirectX and OpenGL (and, in modern projects, also Vulkan, Metal and CUDA).

🕹️ Видеоигры и графика🕹️ Video games and graphics

GPU рендерит сложные 3D-сцены — освещение, тени, текстуры, тысячи листьев на деревьях, отражения. A GPU (Graphics Processing Unit) is a specialised co-processor with thousands of simple cores designed for massive parallelism. Originally built to render graphics by manipulating image memory for the display, GPUs now power many compute-heavy workloads. 🧩 Архитектура ядер и ISA🧩 Core architecture and ISA

ISA (Instruction Set Architecture) — это набор инструкций, которые процессор может понимать и выполнять. У CPU ISA очень богатая: системные инструкции, сложные ветвления, разнообразные арифметические операции — всё, что нужно для универсального ПО. ISA (Instruction Set Architecture) is the set of instructions that a processor can understand and execute. A CPU's ISA is very rich: system instructions, complex branching and a wide range of arithmetic operations — everything needed for general-purpose software.

У GPU ISA заточена под SIMD (Single Instruction, Multiple Data) — одну операцию над большим набором данных одновременно. Также GPU имеют специальные инструкции для текстурирования: интерполяция пикселей, выборка текстур. A GPU's ISA is tailored to SIMD (Single Instruction, Multiple Data) — one operation on a large set of data at the same time. GPUs also have special instructions for texturing: pixel interpolation and texture sampling.

У CPU есть branch prediction и out-of-order execution — они «угадывают», какая инструкция понадобится дальше, и подгружают её заранее. GPU этим почти не занимаются — у них и так есть, чем заполнить ядра. CPUs have branch prediction and out-of-order execution — they "guess" which instruction will be needed next and load it in advance. GPUs hardly do this at all, because they already have plenty of work to fill their cores.

💾 Память: low latency vs high throughput💾 Memory: low latency vs high throughput

CPU использует многоуровневую иерархию кэшей (L1, L2, L3), чтобы данные были как можно ближе. Цель — минимальная задержка: процессор переключается между задачами и должен мгновенно получать данные. В многоядерных CPU работает cache coherence — протоколы, обеспечивающие согласованность данных между кэшами. The CPU uses a multi-level cache hierarchy (L1, L2, L3) to keep data as close as possible. The goal is minimum latency: the processor switches between tasks and must get data almost instantly. In multi-core CPUs, cache coherence applies: protocols that keep data consistent across the caches.

GPU использует унифицированную память и память с высокой пропускной способностью (HBM). Цель — прокачать огромные объёмы данных в тысячи ядер. Задержка отдельного запроса не так важна, как общая «ширина канала». The GPU uses unified memory and high-bandwidth memory (HBM). The goal is to move huge volumes of data into thousands of cores. The latency of a single request matters less than the overall bandwidth.

Ядра могут работать независимо — каждое выполняет свой поток (thread) или процесс. ОС распределяет задачи между ядрами по алгоритмам планирования. Cores can work independently — each one runs its own thread or process. The OS distributes tasks between the cores using scheduling algorithms.

Или ядра могут сотрудничать — одну большую задачу делят на части, каждая часть идёт на своё ядро (parallel processing). Например, в quad-core CPU задачу делят на 4 куска. For example, in a quad-core CPU the task is split into 4 pieces. This requires synchronization through the L2/L3 cache or shared variables.

Более «агрессивный» подход: выбрасывает часть данных, которые человек вряд ли заметит. Достигается значительно более высокая степень сжатия — иногда в 10–100 раз. Lossy compression can average each 2×2 block to grey — the result is a 2×2 grey picture. The original cannot be restored, but the overall impression is kept.

Использует perceptual redundancy — факт, что зрение и слух человека не замечают тонких различий: высоких частот, мелких градиентов, тихих звуков рядом с громкими. It uses perceptual redundancy — the fact that human sight and hearing do not notice fine differences: high frequencies, small gradients, quiet sounds next to loud ones.

A more complex and powerful technique based on mathematical transformations of the data. For example, the DCT (Discrete Cosine Transform) converts a signal from a "time" or "spatial" form into a frequency form.

После преобразования становится видно, какие частоты несут много информации, а какие почти не влияют на восприятие. Малозначимые частоты можно округлить или выбросить (quantization), сильно уменьшив размер файла. After the transformation it becomes clear which frequencies carry a lot of information and which hardly affect perception. Low-significance frequencies can be rounded or discarded (quantization), greatly reducing the size of the file.

Примеры: Salesforce (CRM), SurveyMonkey (опросы), Canva (графический дизайн), Gmail/Google Docs, Microsoft Office 365 (онлайн-версии), Zoom, Microsoft Teams, MoodleCloud.Examples: Salesforce (CRM), SurveyMonkey (surveys), Canva (graphic design), Gmail/Google Docs, Microsoft Office 365 (online versions), Zoom, Microsoft Teams, MoodleCloud.

🛠️ PaaS — Platform as a Service

Готовая среда для разработчиков: ОС, базы данных, middleware, сетевая инфраструктура, инструменты разработки. Разработчик пишет только код приложения, не возится с серверами. A ready-made environment for developers: OS, databases, middleware, network infrastructure, development tools. The developer writes only the application code and does not have to deal with servers.

Характеристики:Features:

  • DevOps-friendly: ускоряет циклы разработки и развёртывания.DevOps-friendly: speeds up development and deployment cycles.
  • Абстракция инфраструктуры: обновления ОС, БД и сети делает провайдер.Infrastructure abstraction: the provider handles updates to the OS, DB and network.
  • Снижение операционных расходов: не нужно покупать и поддерживать железо/ПО.Lower operating costs: there is no need to buy and maintain hardware or software.

Примеры: Google App Engine, Heroku, Microsoft Azure App Service, Amazon Elastic Beanstalk, Red Hat OpenShift.Examples: Google App Engine, Heroku, Microsoft Azure App Service, Amazon Elastic Beanstalk, Red Hat OpenShift.

Пример из учебника: студент Алекс хочет создать фитнес-приложение FitTrack. У него мало опыта администрирования серверов. С PaaS Алекс просто пишет код, а платформа сама масштабирует приложение, обновляет ОС и решает вопросы безопасности. Example from the textbook: a student, Alex, wants to create a fitness app called FitTrack. He has little experience of server administration. With PaaS, Alex simply writes the code, and the platform scales the app, updates the OS and deals with security.

🏗️ IaaS — Infrastructure as a Service

Виртуальные серверы, хранилище и сеть через интернет. Бизнес сам ставит ОС, настраивает ПО, конфигурирует инфраструктуру — но не покупает физическое железо. Virtual servers, storage and network over the internet. The business installs the OS itself, configures the software and sets up the infrastructure — but does not buy physical hardware.

Опирается на виртуализацию: одна физическая машина «делится» на множество виртуальных машин (VM), у каждой свой OS и приложения, работающих изолированно. It relies on virtualization: one physical machine is "divided" into many virtual machines (VMs), each with its own OS and applications, running in isolation.

Характеристики:Features:

  • Кастомизация: можно настроить инфраструктуру под любые требования.Customization: the infrastructure can be configured to any requirements.
  • Масштабируемость: ресурсы быстро добавляются и убираются.Scalability: resources are quickly added and removed.
  • Контроль: бизнес полностью управляет конфигурацией и ПО.Control: the business fully manages the configuration and software.

Примеры: Amazon Web Services (AWS), Microsoft Azure, Google Cloud Platform, IBM Cloud, Oracle Cloud Infrastructure, Linode.Examples: Amazon Web Services (AWS), Microsoft Azure, Google Cloud Platform, IBM Cloud, Oracle Cloud Infrastructure, Linode.

🇬🇧 English summary (click to expand)

Cloud computing delivers computing resources — servers, storage, databases and software — over the internet from remote data centres, on a pay-for-what-you-use basis. Three service models differ by level of control and what the provider manages. SaaS (Software as a Service) delivers a ready-to-use application via a browser or mobile app; the provider runs everything, so the user simply consumes (examples: Gmail, Salesforce, Canva, Microsoft 365, Zoom). PaaS (Platform as a Service) supplies a development platform — OS, databases, middleware, tooling — so developers focus only on writing application code (examples: Heroku, Google App Engine, AWS Elastic Beanstalk). IaaS (Infrastructure as a Service) provides virtualised servers, storage and networking; the customer installs and configures their own OS and software, gaining maximum control (examples: AWS, Microsoft Azure, Google Cloud). IaaS relies on virtualisation, which splits one physical machine into multiple isolated virtual machines (VMs).

📌 Что важно запомнить — экзаменационные подсказки📌 What to remember — exam tips

  • Регистры CPU (IR, PC, MAR, MDR, AC) — выучи назначение каждого. На экзамене часто просят описать роль конкретного регистра в FDE-цикле.CPU registers (IR, PC, MAR, MDR, AC) — learn the purpose of each one. In the exam you are often asked to describe the role of a particular register in the FDE cycle.
  • Шины: различай адресная (что), данных (то самое содержимое), управления (сигнал). Помни: адресная — однонаправленная, данных — двунаправленная.Buses: distinguish between the address bus (what), the data bus (the content itself) and the control bus (the signal). Remember: the address bus is unidirectional, the data bus is bidirectional.
  • FDE-цикл — основа экзамена. Запомни последовательность регистров: PC → MAR → MDR → IR → CU → ALU/память.The FDE cycle is the core of the exam. Learn the sequence of registers and units: PC → MAR → MDR → IR → CU → ALU/memory.
  • CPU vs GPU (HL): отвечай по парам — мало мощных ядер vs тысячи простых; low latency vs high throughput; универсальность vs параллелизм.CPU vs GPU (HL): answer in pairs — few powerful cores vs thousands of simple ones; low latency vs high throughput; versatility vs parallelism.
  • Volatile vs Non-volatile — лёгкий, но частый вопрос. RAM теряет, ROM/SSD/HDD сохраняют.Volatile vs non-volatile — an easy but common question. RAM loses its data; ROM, SSD and HDD keep it.
  • Cache hit/miss — связывай с производительностью: больше hit = быстрее программа.Cache hit/miss — link it to performance: more hits = a faster program.
  • Pipelining (HL): отвечай через аналогию со стиркой — наглядно и легко запомнить.Pipelining (HL): answer with the laundry analogy — it is vivid and easy to remember.
  • HDD vs SSD: механика vs flash; медленно vs быстро; дёшево vs дорого; шумно vs тихо.HDD vs SSD: mechanics vs flash; slow vs fast; cheap vs expensive; noisy vs quiet.
  • Lossless vs Lossy: идентично vs с потерями; меньшая степень vs большая; код/документы vs фото/аудио.Lossless vs lossy: identical vs with loss; lower ratio vs higher ratio; code/documents vs photos/audio.
  • RLE — умей сжать любую строку повторов и объяснить, что компрессия работает только для повторяющихся данных.RLE — be able to compress any run of repeats and explain that the method works only for repeated data.
  • Cloud — SaaS/PaaS/IaaS: отвечай через уровень контроля (SaaS низкий, IaaS высокий) и что предоставляется (приложение / платформа / инфраструктура).Cloud — SaaS/PaaS/IaaS: answer in terms of the level of control (SaaS low, IaaS high) and what is provided (application / platform / infrastructure).
