1. С чего начать: триада CIA и общая картина1. Getting started: the CIA triad and the big picture

English summary · CIA triad

Network security is built around three goals, known as the CIA triad:

  • Confidentiality — only intended recipients can read the data (achieved with encryption, access control, authentication).
  • Integrity — data is not altered in transit or at rest (achieved with hashing, digital signatures, checksums).
  • Availability — the service is reachable when needed (achieved with DDoS protection, backups, redundancy).

Almost any A2.4 exam question maps to one of these three letters: name which goal a technology protects or breaks and half the answer is already written.

2. 🛡️ Межсетевые экраны (Firewalls) — подтема A2.4.12. 🛡️ Firewalls — subtopic A2.4.1

English summary · Firewalls (A2.4.1)

A firewall is hardware or software that inspects packets entering and leaving a network and applies an ordered rule set based on source/destination IP, port number, and protocol. Next-generation firewalls (NGFW, layer 7) also inspect packet contents via deep packet inspection.

  • Whitelist — deny by default, allow only listed sources (safer).
  • Blacklist — allow by default, block listed sources (must know every attacker in advance).

Strengths: access control, traffic logging and alerting, layer-7 filtering, easy scaling. Limitations: blind to insider threats, bypassed by sophisticated or zero-day attacks hidden in encrypted traffic, hard to configure, and DPI adds latency.

NAT hides internal IP addresses behind one public address (IP masquerading) — a basic form of access control on top of address conservation.

Файрвол (firewall) — это устройство или программа, которая отслеживает и фильтрует входящий и исходящий сетевой трафик на уровне пакетов. Современные файрволы «нового поколения» (next-generation firewall, NGFW), они же layer 7-файрволы, умеют смотреть не только заголовки пакетов, но и сам контент. A firewall is a device or program that monitors and filters incoming and outgoing network traffic at the packet level. Modern next-generation firewalls (NGFW), also known as layer 7 firewalls, can look not only at packet headers but also at the content itself.

Как файрвол принимает решениеHow a firewall makes a decision

Файрвол проверяет каждый пакет, который пытается войти или выйти, и применяет к нему набор правил. Правила опираются на: A firewall checks every packet that tries to enter or leave and applies a set of rules to it. The rules are based on:

  • IP-адреса источника и назначения;source and destination IP addresses;
  • Номера портов (например, 80 — HTTP, 443 — HTTPS, 22 — SSH);port numbers (for example, 80 for HTTP, 443 for HTTPS, 22 for SSH);
  • Протоколы (TCP, UDP);protocols (TCP, UDP);
  • Для NGFW — содержимое пакета (deep packet inspection, DPI).for NGFW, the packet content (deep packet inspection, DPI).

Правила обрабатываются по порядку. Файрвол идёт сверху вниз; как только нашёл совпадение — выполняет действие (allow или block) и останавливается. Rules are processed in order. The firewall goes from top to bottom; as soon as it finds a match, it applies the action (allow or block) and stops.

Список запрещённых IP-адресов, доменов или приложений. Всё, чего нет в списке — пропускается по умолчанию. Требует знать всех плохих заранее — отсюда дыры.A list of blocked IP addresses, domains or applications. Anything not on the list is allowed by default. It requires knowing all the bad ones in advance, which is why it leaves gaps.

NAT как дополнительная защитаNAT as an extra layer of protection

Network Address Translation (NAT) — это не только способ экономить IPv4-адреса, но и слой защиты. NAT прячет внутренние IP-адреса за одним публичным («IP masquerading»), и атакующий извне просто не знает, к какому именно внутреннему устройству ему стучаться. Это базовая форма контроля доступа к внутренней сети. Network Address Translation (NAT) is not only a way to save IPv4 addresses but also a layer of protection. NAT hides internal IP addresses behind one public address (“IP masquerading”), so an outside attacker simply does not know which internal device to target. It is a basic form of access control for the internal network.

🌍 Реальный пример: в любой домашней Wi-Fi-сети маршрутизатор использует NAT. Твой ноутбук имеет адрес типа 192.168.1.5, но в интернете «видится» как один публичный IP роутера. Атакующий не может напрямую направить пакет на твой ноутбук — сначала надо пробить NAT. 🌍 Real example: in any home Wi-Fi network, the router uses NAT. Your laptop has an address such as 192.168.1.5, but on the internet it appears as the one public IP address of the router. An attacker cannot send a packet directly to your laptop — they would first have to get past the NAT.

3. ⚠️ Распространённые сетевые уязвимости — подтема A2.4.23. ⚠️ Common network vulnerabilities — subtopic A2.4.2

English summary · Common network vulnerabilities (A2.4.2)

A vulnerability is a weakness an attacker can exploit. Core IB CS list:

  • DDoS — botnet floods a service so legitimate users are locked out (hits Availability).
  • Insecure protocols — Telnet, FTP send credentials as cleartext, easy to sniff.
  • Malware — virus (attached to a host program), worm (self-spreading across networks), trojan (disguised as legitimate software), ransomware (encrypts files for payment), spyware (silently exfiltrates data).
  • MITM — attacker secretly relays between two endpoints, often via a rogue Wi-Fi access point.
  • Phishing / social engineering — fake messages trick users into revealing credentials.
  • SQL injection — malicious SQL fragments in input fields execute against the database.
  • Cross-site scripting (XSS) — injected scripts run inside other users' browsers.
  • Brute force / weak authentication — automated password guessing against poorly protected logins.
  • Unpatched software — known fixes exist but were not installed (e.g. Equifax 2017).
  • Zero-day exploits — attacks against unknown vulnerabilities with no patch available (e.g. Heartbleed).

Уязвимость (vulnerability) — это слабое место в системе, через которое возможна атака. Ниже — десять ключевых уязвимостей, которые требует знать IB CS. A vulnerability is a weakness in a system through which an attack is possible. Below are ten key vulnerabilities that IB CS requires you to know.

🌊 DDoS — Distributed Denial of Service

Цель — перегрузить сайт или сервис огромным количеством запросов из множества источников, чтобы он стал недоступен легальным пользователям. Атакует Availability из триады CIA.The aim is to overload a website or service with a huge number of requests from many sources, so that legitimate users cannot reach it. It attacks Availability from the CIA triad.

Пример: интернет-магазин падает во время большой распродажи под потоком трафика с тысяч заражённых компьютеров (ботнет).Example: an online shop crashes during a big sale under a flood of traffic from thousands of infected computers (a botnet).

📡 Небезопасные протоколы (Insecure network protocols)📡 Insecure network protocols

Протоколы, в которых данные передаются в открытом виде, без шифрования. Их легко перехватить и прочитать.Protocols that send data in plain text, without encryption. Such data is easy to intercept and read.

Пример: использование Telnet или FTP для удалённого доступа — пароли и данные летят по сети открытым текстом.Example: using Telnet or FTP for remote access — passwords and data travel across the network in plain text.

🦠 Malware (вредоносное ПО)🦠 Malware

Программное обеспечение, созданное, чтобы повредить, нарушить работу или получить несанкционированный доступ к системе. Семейство включает:Software designed to damage, disrupt or gain unauthorised access to a system. The family includes:

  • Вирус (virus) — встраивается в другие программы, заражает их при запуске.Virus — embeds itself in other programs and infects them when they run.
  • Червь (worm) — самораспространяющийся, не нуждается в программе-носителе, расползается по сети сам.Worm — self-replicating; it does not need a host program and spreads across the network on its own.
  • Троян (trojan) — маскируется под полезную программу, внутри — вредоносный код.Trojan — disguises itself as a useful program but contains malicious code.
  • Ransomware (вымогатель) — шифрует файлы жертвы и требует выкуп за расшифровку.Ransomware — encrypts the victim’s files and demands a ransom for the decryption.
  • Spyware (шпионское ПО) — тайно собирает данные о пользователе (пароли, кейлоггинг, история).Spyware — secretly collects data about the user (passwords, keylogging, browsing history).
Пример: ransomware шифрует файлы на компьютере жертвы и требует биткойны за ключ расшифровки.Example: ransomware encrypts files on the victim’s computer and demands bitcoin for the decryption key.
🌍 Реальный случай — WannaCry (2017): червь-вымогатель использовал уязвимость Windows (EternalBlue), за несколько дней заразил более 200 000 компьютеров в 150 странах, парализовал работу британской NHS, заводов Renault и Honda. Microsoft выпускала патч за 2 месяца до атаки — но многие не обновились. Это самый известный пример того, почему важен patch management. 🌍 Real case — WannaCry (2017): a ransomware worm exploited a Windows vulnerability (EternalBlue), infected more than 200,000 computers in 150 countries within a few days, and paralysed work at the British NHS and at Renault and Honda factories. Microsoft had released a patch two months before the attack, but many systems had not been updated. It is the best-known example of why patch management matters.

👤 Man-in-the-Middle (MITM, «человек посередине»)👤 Man-in-the-middle (MITM)

Атакующий тайно вклинивается между двумя сторонами, которые думают, что общаются напрямую. Может читать и подменять сообщения.The attacker secretly inserts themselves between two parties who think they are communicating directly. They can read and alter the messages.

Пример: атакующий поднимает фальшивую Wi-Fi-точку в кафе, перехватывает данные карт при онлайн-покупках.Example: an attacker sets up a fake Wi-Fi hotspot in a café and intercepts card details during online purchases.

🎣 Phishing (фишинг) и социальная инженерия🎣 Phishing and social engineering

Обманные попытки выманить чувствительные данные (логины, пароли, реквизиты карт), выдавая себя за доверенную сторону. Это форма социальной инженерии (social engineering) — атаки на человека, а не на технологию.Deceptive attempts to obtain sensitive data (logins, passwords, card details) by pretending to be a trusted party. It is a form of social engineering — an attack on people rather than on technology.

Пример: письмо «из банка» с просьбой подтвердить данные на фальшивом сайте, копирующем дизайн настоящего.Example: an email “from the bank” asks the user to confirm their details on a fake website that copies the design of the real one.

💉 SQL-инъекция💉 SQL injection

Атака, при которой во входное поле (поиск, форма логина) вставляется специально сконструированный SQL-код, который сервер выполняет и выдаёт защищённые данные или меняет базу.An attack in which specially crafted SQL code is entered into an input field (search, login form), and the server runs it and reveals protected data or changes the database.

Пример: в поле поиска вводится ' OR '1'='1 — и сайт показывает данные всех пользователей.Example: the string ' OR '1'='1 is entered into the search box, and the site shows the data of all users.

📜 Cross-Site Scripting (XSS)

Уязвимость веб-приложений: атакующий внедряет вредоносный скрипт в контент, который потом видят другие пользователи. Скрипт выполняется в их браузерах.A web application vulnerability: the attacker injects a malicious script into content that other users later see. The script runs in their browsers.

Пример: комментарий на блоге содержит JavaScript, который ворует cookie-сессии у тех, кто прочитает пост.Example: a blog comment contains JavaScript that steals session cookies from anyone who reads the post.

🔑 Brute force и слабая аутентификация🔑 Brute force and weak authentication

Атакующий перебирает пароли (brute force) или использует «словарные» атаки. Уязвимость усиливается, если пароли простые, нет блокировки после N неверных попыток или нет MFA.The attacker tries passwords one after another (brute force) or uses dictionary attacks. The risk increases if passwords are simple, there is no lock-out after N failed attempts, or there is no MFA.

Пример: сайт требует только логин и простой пароль, без второго фактора — атакующий за часы подбирает пароль password123.Example: a site asks only for a login and a simple password, with no second factor — the attacker guesses the password password123 within hours.

🩹 Необновлённое ПО (unpatched software)🩹 Unpatched software

ПО, в котором не установлены последние патчи безопасности. Известные уязвимости опубликованы — но конкретная система к ним всё ещё уязвима.Software that has not had the latest security patches installed. Known vulnerabilities are published, but a particular system is still vulnerable to them.

Пример: ОС без обновлений несколько лет — атакующие используют любые известные дыры.Example: an operating system that has not been updated for several years — attackers use any known holes.
🌍 Реальный случай — Equifax (2017): утечка персональных данных 147 миллионов американцев. Причина: компания не установила вышедший за 2 месяца патч для веб-фреймворка Apache Struts. Прямой урок: patch management — не бюрократия, а защита. 🌍 Real case — Equifax (2017): a leak of the personal data of 147 million Americans. The cause: the company did not install a patch for the Apache Struts web framework that had been released two months earlier. The direct lesson: patch management is not bureaucracy, it is protection.

0️⃣ Zero-day exploits

Атаки, использующие ранее неизвестную уязвимость — до того, как разработчик выпустил патч и общественность узнала о проблеме. Самые опасные, потому что защититься нечем.Attacks that use a previously unknown vulnerability — before the developer has released a patch and the public knows about the problem. They are the most dangerous, because there is no defence against them.

Пример: атакующий находит дыру в популярном браузере и пишет эксплойт раньше, чем разработчики успевают выпустить обновление.Example: an attacker finds a hole in a popular browser and writes an exploit before the developers manage to release an update.
🌍 Реальный случай — Heartbleed (2014): уязвимость в OpenSSL (библиотека для HTTPS) позволяла читать содержимое памяти серверов — включая закрытые ключи и пароли. Дыра существовала два года, прежде чем её нашли. Затронуты были две трети всех HTTPS-сайтов в интернете. 🌍 Real case — Heartbleed (2014): a vulnerability in OpenSSL (a library used for HTTPS) allowed the contents of server memory to be read, including private keys and passwords. The hole existed for two years before it was found. Two thirds of all HTTPS sites on the internet were affected.

4. 🛡️ Контрмеры (Countermeasures) — подтема A2.4.34. 🛡️ Countermeasures — subtopic A2.4.3

English summary · Countermeasures (A2.4.3)

Each vulnerability has matching defences. The IB list covers technical and policy controls:

  • CSP restricts script sources in the browser, stopping XSS injection.
  • Strong password policies raise length and complexity, blocking dictionary and brute-force attempts.
  • Encrypted protocols (HTTPS / SSH) protect traffic from eavesdropping and MITM.
  • SSL/TLS certificates prove server identity so HTTPS resists impersonation.
  • Patch management closes known exploits before attackers reach them.
  • DDoS mitigation filters malicious flood traffic at the network edge.
  • Input validation blocks SQL injection and XSS at the server.
  • Email filtering catches phishing and malware attachments.
  • IDS detects intrusions and raises alerts (passive); IPS detects and actively blocks (inline).
  • MFA / 2FA requires multiple factors — knowledge, possession, biometrics — defeating credential leaks.
  • VPN creates an encrypted tunnel for safe use of untrusted networks.
  • Authentication: passwords, MFA, biometrics, SSO, OAuth (delegated authorisation; OIDC adds authentication).
  • Access control: RBAC assigns rights by role; least privilege grants the minimum needed; ACLs list permissions per resource.
  • Wireless: MAC filtering plus WPA2/WPA3 — but MAC spoofing limits filtering alone.
  • Penetration testing and security awareness training close human and configuration gaps.

На каждую уязвимость существует своя контрмера. IB CS перечисляет следующие основные политики и инструменты защиты: Each vulnerability has its own countermeasure. IB CS lists the following main policies and protection tools:

📋 Content Security Policy (CSP)

Браузерный механизм, который предотвращает XSS. CSP диктует браузеру, с каких доменов разрешено загружать скрипты, стили и изображения.A browser mechanism that prevents XSS. CSP tells the browser which domains it may load scripts, styles and images from.

Защищает от: XSSProtects against: XSS

Пример: сайт устанавливает CSP, разрешающую скрипты только со своего домена и доверенного CDN — это блокирует попытки внедрить чужой код.Example: a site sets a CSP that allows scripts only from its own domain and a trusted CDN — this blocks attempts to inject someone else’s code.

🔐 Сложные политики паролей🔐 Strong password policies

Правила требующие сильные пароли: микс заглавных/строчных, цифр, символов, минимальная длина. Часто включают истечение срока и запрет повторного использования.Rules that require strong passwords: a mix of upper- and lower-case letters, digits and symbols, and a minimum length. They often include password expiry and a ban on password reuse.

5. 🔐 Шифрование и цифровые сертификаты — подтема A2.4.45. 🔐 Encryption and digital certificates — subtopic A2.4.4

English summary · Encryption & certificates (A2.4.4)

Encryption converts plaintext into ciphertext that only the holder of the correct key can decrypt.

  • Symmetric — one shared secret key encrypts and decrypts (AES, DES). Fast, low CPU; the hard part is distributing the key safely. Used for bulk data (files, video).
  • Asymmetric / public-key — a public-private key pair (RSA, ECC). The public key encrypts or verifies; the private key decrypts or signs. Slower but no pre-shared secret needed. Used for key exchange and digital signatures.
  • Hybrid (TLS) — asymmetric exchanges a symmetric session key, then symmetric encrypts the actual traffic — combining safety and speed.
  • Digital certificates bind a public key to an identity. A trusted Certificate Authority signs the certificate; browsers verify the CA signature to trust the site, then run TLS to set up HTTPS.
  • Digital signatures sign a document's hash with the sender's private key; the recipient verifies with the public key — providing authentication and integrity (not secrecy).
  • Hashing is a one-way, deterministic function with avalanche effect (SHA-256 today; MD5/SHA-1 are broken). Used for file integrity, password storage with salt (bcrypt, Argon2), and signatures.
  • Key management covers safe generation, rotation, backup, and restricted access — required by GDPR, HIPAA, PCI DSS.

Шифрование (encryption) — процесс превращения данных в закодированную форму, чтобы их не мог прочитать никто, кроме адресата. Алгоритмы превращают открытый текст (plaintext) в шифртекст (ciphertext), который можно расшифровать только при наличии правильного ключа. Encryption is the process of converting data into a coded form so that nobody except the intended recipient can read it. Algorithms turn plaintext into ciphertext, which can be decrypted only with the correct key.

Симметричное vs асимметричное шифрованиеSymmetric vs asymmetric encryption

🔑 Симметричное шифрование🔑 Symmetric encryption

Один и тот же секретный ключ используется и для шифрования, и для расшифровки. Стороны должны заранее безопасно обменяться ключом.The same secret key is used for both encryption and decryption. The parties must exchange the key securely in advance.

Алгоритмы: AES, DES, 3DES.Algorithms: AES, DES, 3DES.

Плюс: очень быстро, мало нагружает процессор.Advantage: very fast, puts little load on the processor.

Минус: проблема распространения ключа — как безопасно передать ключ собеседнику?Disadvantage: the problem of key distribution — how to pass the key to the other party securely?

🗝️ Асимметричное шифрование (public-key)🗝️ Asymmetric encryption (public-key)

Используется пара ключей: публичный (открыто раздаётся всем) и приватный (хранится в секрете владельцем).A pair of keys is used: a public key (openly shared with everyone) and a private key (kept secret by its owner).

То, что зашифровано публичным ключом, расшифровать можно только приватным — и наоборот.What is encrypted with the public key can be decrypted only with the private key — and vice versa.

Алгоритмы: RSA, ECC, ElGamal.Algorithms: RSA, ECC, ElGamal.

Плюс: не нужно безопасно передавать ключ заранее.Advantage: there is no need to pass the key securely in advance.

Минус: в десятки раз медленнее симметричного.Disadvantage: tens of times slower than symmetric encryption.

Цифровой сертификат — электронный документ, который связывает публичный ключ с идентичностью (имя человека/организации, домен).   • SSH-ключи — для безопасного удалённого входа на серверы без пароля.SSH keys — for secure remote login to servers without a password.
  • Code signing — разработчик подписывает программу. Пользователь при запуске видит, что код от настоящего автора и не был изменён.Code signing — a developer signs a program. When the program is launched, the user can see that the code comes from the genuine author and has not been changed.
  • VPN — сервер и клиент аутентифицируются через сертификаты, прежде чем устанавливать туннель.VPN — the server and the client authenticate each other with certificates before the tunnel is set up.
  • Подпись документов — PDF, Word: подтверждает автора и целостность.Signing documents — PDF, Word: confirms the author and integrity.

Цифровые подписи (digital signatures)Digital signatures

Подпись использует асимметричное шифрование наоборот: подписывают приватным ключом, проверяют — публичным. Цель — не секретность, а подтверждение авторства и целостности. A signature uses asymmetric encryption in reverse: it is created with the private key and checked with the public key. The aim is not secrecy but confirmation of authorship and integrity.

  1. Отправитель берёт документ и считает его хеш (короткий уникальный «отпечаток»).The sender takes the document and calculates its hash (a short, unique “fingerprint”).
  2. Шифрует этот хеш своим приватным ключом — получается цифровая подпись.Encrypts this hash with the sender’s private key — the result is a digital signature.
  3. Прикрепляет подпись к документу и отправляет.Attaches the signature to the document and sends it.
  4. Получатель расшифровывает подпись публичным ключом отправителя — получает хеш.The recipient decrypts the signature with the sender’s public key and obtains the hash.
  5. Сам вычисляет хеш из полученного документа.Calculates the hash of the received document independently.
  6. Если хеши совпадают — документ не изменён и действительно от этого отправителя.If the hashes match, the document is unchanged and really comes from this sender.

Хеш-функции (hashing)Hash functions (hashing)

Хеш-функция — алгоритм, который превращает любой ввод (текст, файл) в строку фиксированной длины. Свойства: A hash function is an algorithm that turns any input (text, file) into a string of fixed length. Its properties:

  • Односторонняя: по хешу нельзя восстановить исходные данные.One-way: the original data cannot be recovered from the hash.
  • Детерминированная: один и тот же ввод всегда даёт один и тот же хеш.Deterministic: the same input always gives the same hash.
  • Лавинный эффект: малейшее изменение ввода полностью меняет хеш.Avalanche effect: the smallest change to the input completely changes the hash.

Пример: MD5(«Hello, world!») = 6cd3556deb0da54bca060b4c39479839. Поменяй заглавную H на строчную h — хеш будет совершенно другой.Example: MD5(“Hello, world!”) = 6cd3556deb0da54bca060b4c39479839. Change the capital H to a lowercase h — the hash will be completely different.

Где используется: проверка целостности файлов; хранение паролей (сохраняют не сам пароль, а его хеш + salt); цифровые подписи; уникальные идентификаторы.Where it is used: checking the integrity of files; storing passwords (not the password itself, but its hash + salt); digital signatures; unique identifiers.

⚠️ MD5 и SHA-1 — устарели⚠️ MD5 and SHA-1 are obsolete

MD5 и SHA-1 уязвимы к коллизиям (когда два разных ввода дают одинаковый хеш) — нельзя использовать для безопасности. Современный стандарт — SHA-256 (или SHA-3). Для хранения паролей используют специальные функции: bcrypt, Argon2, scrypt — они нарочно медленные, чтобы усложнить brute force.MD5 and SHA-1 are vulnerable to collisions (when two different inputs give the same hash) and must not be used for security. The modern standard is SHA-256 (or SHA-3). For storing passwords, special functions are used: bcrypt, Argon2, scrypt — they are deliberately slow, to make brute force harder.

Управление ключами шифрования (key management)Encryption key management

Шифрование бесполезно, если ключи скомпрометированы. Key management — процесс безопасной генерации, хранения, ротации и резервного копирования ключей. Encryption is useless if the keys are compromised. Key management is the process of generating, storing, rotating and backing up keys securely.

  • Ключи доступны только авторизованным сторонам.Keys are available only to authorised parties.
  • Регулярная ротация ключей снижает риски при утечке.Regular key rotation reduces the risks if a key leaks.
  • Резервные копии ключей — иначе потеря ключа = потеря доступа к данным навсегда.Key backups: otherwise losing a key means losing access to the data permanently.
  • Регуляторы (GDPR, HIPAA, PCI DSS) требуют строгого управления ключами; нарушение = большие штрафы.Regulators (GDPR, HIPAA, PCI DSS) require strict key management; a breach means large fines.

6. 📜 Политики безопасности и приватность6. 📜 Security policies and privacy

English summary · Policies & privacy
  • Backup strategy — the 3-2-1 rule: three copies, two media types, one off-site. Full backups are simple to restore; incremental backups are fast to run. Restores must be tested regularly.
  • Patch management — track, test, and deploy security patches on a schedule. Lapses cause mass breaches (Equifax, WannaCry).
  • Incident response — six phases: preparation, identification, containment, eradication, recovery, lessons learned.
  • GDPR — EU privacy law (2018). Core principles include lawful basis, data minimisation, purpose limitation, right to erasure, 72-hour breach notification, and fines up to 4% of global turnover.
  • Encryption in transit protects data on the network (HTTPS/TLS, SSH, VPN); encryption at rest protects stored data (full-disk encryption, TDE, cloud server-side encryption). Mature security uses both — losing either layer exposes the data.

Резервное копирование (backup strategies)Backup strategies

Защита от потери данных при сбое, ransomware, ошибке пользователя или физическом уничтожении. Protection against data loss caused by a failure, ransomware, user error or physical destruction.

  • Правило 3-2-1: минимум 3 копии данных на 2 разных типах носителя, 1 — вне основной локации (off-site/облако).The 3-2-1 rule: at least 3 copies of the data on 2 different types of media, with 1 copy off-site (in another location or the cloud).
  • Full backup — полная копия всего; долго, но восстанавливается просто.Full backup — a complete copy of everything; slow to make, but simple to restore.
  • Incremental backup — только то, что изменилось с прошлого бэкапа; быстро делать, дольше восстанавливать.Incremental backup — only what has changed since the last backup; quick to make, slower to restore.
  • Проверка восстановления! Бэкап без регулярной проверки — это игра в надежду.Test your restores! A backup without regular checks is wishful thinking.

Управление обновлениями (patch management)Patch management

Систематический процесс: отслеживать выходящие патчи, тестировать их, ставить на все системы в разумные сроки. Без этого появляются «висящие» уязвимости — главный путь массовых атак (см. Equifax, WannaCry). A systematic process: track newly released patches, test them, and install them on all systems within a reasonable time. Without this, unpatched vulnerabilities remain open — the main route for mass attacks (see Equifax, WannaCry).

Реагирование на инциденты (incident response)Incident response

Когда атака уже случилась — нужен план. Классические этапы:When an attack has already happened, a plan is needed. The classic stages are:

  1. Preparation — план и команда подготовлены заранее.Preparation — a plan and a team are ready in advance.
  2. Identification — обнаружение, что произошёл инцидент.Identification — detecting that an incident has happened.
  3. Containment — изоляция, чтобы не распространилось дальше.Containment — isolating the problem so that it does not spread further.
  4. Eradication — удаление вредоносного кода и причины.Eradication — removing the malicious code and its cause.
  5. Recovery — восстановление сервисов из бэкапов.Recovery — restoring services from backups.
  6. Lessons learned — разбор полётов: что улучшить.Lessons learned — a review of what happened and what to improve.

Приватность и регулированиеPrivacy and regulation

🇪🇺 GDPR — General Data Protection Regulation

Закон ЕС о защите персональных данных (с 2018). Ключевые принципы:The EU law on the protection of personal data (since 2018). Key principles:

  • Lawfulness — обработка только на законных основаниях (согласие, контракт, закон).Lawfulness — processing only on a lawful basis (consent, contract, law).
  • Data minimization (минимизация данных) — собирать только то, что действительно нужно, не «на всякий случай».Data minimisation — collecting only what is really needed, not “just in case”.
  • Purpose limitation — данные используются только для заявленной цели.Purpose limitation — data is used only for the stated purpose.
  • Right to erasure («право быть забытым») — пользователь может потребовать удалить свои данные.Right to erasure (“right to be forgotten”) — the user can ask for their data to be deleted.
  • Breach notification — об утечке нужно сообщить за 72 часа.Breach notification — a data breach must be reported within 72 hours.
  • Штрафы — до 4% мирового оборота компании.Fines — up to 4% of the company’s global turnover.

Шифрование at-rest vs in-transitEncryption at rest vs in transit

ТипTypeЧто значитWhat it meansЧем достигаетсяHow it is achieved
Encryption in transit Данные шифруются во время передачи по сети.Data is encrypted during transmission over the network. HTTPS/TLS, SSH, VPN, шифрованный email (S/MIME, PGP).HTTPS/TLS, SSH, VPN, encrypted email (S/MIME, PGP).
Encryption at rest Данные шифруются в хранилище (диск, база данных, бэкап).Data is encrypted in storage (disk, database, backup). Full disk encryption (BitLocker, FileVault, LUKS), TDE в БД, шифрование объектов в облаке (S3 SSE).Full disk encryption (BitLocker, FileVault, LUKS), TDE in databases, encryption of objects in the cloud (S3 SSE).

Зрелая защита требует и того, и другого: HTTPS защищает данные в пути, дисковое шифрование защищает их в покое. Если шифровать только in-transit, то украденный жёсткий диск выдаёт всё. Если только at-rest — данные перехватываются по сети. Mature protection requires both: HTTPS protects data in transit, and disk encryption protects it at rest. If only in-transit encryption is used, a stolen hard disk reveals everything. If only at-rest encryption is used, data can be intercepted on the network.

7. Что важно запомнить (экзаменационные подсказки)7. What to remember (exam tips)

  • Любой ответ по A2.4 проще структурировать через триаду CIA (Confidentiality, Integrity, Availability) — назови, какую цель защищает или ломает технология.Any A2.4 answer is easier to structure using the CIA triad (Confidentiality, Integrity, Availability) — name the goal that the technology protects or breaks.
  • Файрвол = фильтр трафика по IP/портам/протоколам. Сильные стороны: контроль доступа, мониторинг. Слабые: внутренние угрозы, изощрённые атаки, сложность настройки.Firewall = a traffic filter based on IP addresses, ports and protocols. Strengths: access control, monitoring. Weaknesses: insider threats, sophisticated attacks, complex configuration.
  • Whitelist — что разрешено (безопаснее по умолчанию). Blacklist — что запрещено (требует знать всех плохих).Whitelist — what is allowed (safer by default). Blacklist — what is forbidden (requires knowing all the bad ones).
  • IDS = обнаруживает и сообщает. IPS = обнаруживает и блокирует.IDS = detects and reports. IPS = detects and blocks.
  • Симметричное шифрование — один ключ, быстро, проблема обмена. Асимметричное — пара ключей, медленнее, решает проблему обмена. TLS использует оба в гибридной схеме.Symmetric encryption — one key, fast, but the key exchange is a problem. Asymmetric — a key pair, slower, solves the key exchange problem. TLS uses both in a hybrid scheme.
  • Цифровой сертификат = публичный ключ + идентичность, подписанные CA. HTTPS работает только с валидным сертификатом.Digital certificate = a public key + an identity, signed by a CA. HTTPS works only with a valid certificate.
  • Цифровая подпись — приватным ключом подписываешь хеш, публичным проверяешь. Даёт аутентификацию + целостность, но не секретность.Digital signature — you sign the hash with the private key and verify it with the public key. It gives authentication + integrity, but not secrecy.
  • MFA — главная защита от слива пароля и brute force. Три фактора: знание / владение / биометрия.MFA — the main protection against password leaks and brute force. Three factors: knowledge / possession / biometrics.
  • Patch management и обучение сотрудников — самые «скучные», но самые эффективные контрмеры (см. WannaCry, Equifax).Patch management and staff training are the most “boring” but also the most effective countermeasures (see WannaCry, Equifax).
  • Часто экзаменационный формат: «опиши, как контрмера X снижает риск уязвимости Y» (3-4 балла). Структура ответа: 1) что такое уязвимость, 2) что делает контрмера, 3) как именно это блокирует атаку.A common exam format: “describe how countermeasure X reduces the risk of vulnerability Y” (3-4 marks). Structure of the answer: 1) what the vulnerability is, 2) what the countermeasure does, 3) how exactly it blocks the attack.
  • NAT — это и экономия IPv4, и безопасность (IP masquerading скрывает внутренние адреса).NAT is both a way to save IPv4 addresses and a security feature (IP masquerading hides internal addresses).
  • Encryption at rest и in transit — нужны оба для зрелой защиты.Encryption at rest and in transit — both are needed for mature protection.
