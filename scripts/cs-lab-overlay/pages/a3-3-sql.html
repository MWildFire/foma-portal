1. Четыре категории SQL1. The four sub-languages of SQL

🌐 EN summary — Four SQL sub-languages. SQL is split into four families by purpose. DDL (Data Definition Language) defines the schema with commands like CREATE, ALTER and DROP. DML (Data Manipulation Language) works with the rows inside tables: SELECT, INSERT, UPDATE, DELETE. DCL (Data Control Language) manages permissions with GRANT and REVOKE. TCL (Transaction Control Language) controls transactions with COMMIT, ROLLBACK and SAVEPOINT. Exam questions often ask which family a given keyword belongs to, so the categorisation matters as much as the syntax itself.

СУБД (Система Управления Базами Данных, англ. Database Management System) использует четыре подсемейства языка SQL. Они отличаются задачей: одни строят структуру, другие работают с данными, третьи управляют доступом, четвёртые — целостностью транзакций. На экзамене любят спрашивать «к какой категории относится команда X?» — выучи эту таблицу. The DBMS (database management system) uses four sub-languages of SQL. They differ in purpose: some build the structure, others work with the data, others control access, and the fourth manages the integrity of transactions. Exam questions often ask "which category does command X belong to?" — learn this table.

💡 Аналогия: DDL — это архитектор (строит здание). DML — жилец (двигает мебель внутри). DCL — охранник (выдаёт пропуска). TCL — нотариус (фиксирует или отменяет сделку). 💡 Analogy: DDL is the architect (builds the building). DML is the tenant (moves the furniture around inside). DCL is the security guard (issues the passes). TCL is the notary (confirms or cancels the deal).

2. DDL — строим структуру базы2. DDL — building the database structure

🌐 EN summary — DDL builds the schema. DDL covers commands that define database structure rather than touch the data itself. CREATE DATABASE makes a new empty database; CREATE TABLE defines columns with data types and optional inline constraints such as primary key or foreign key. ALTER TABLE adds, removes or modifies columns on an existing table, and DROP TABLE deletes the table along with all of its rows. Because DDL changes shape rather than rows, mistakes here are destructive and usually require restoring from a backup.

Эта команда создаёт пустую базу — внутри неё мы потом сделаем таблицы.This command creates an empty database — we will create the tables inside it later.

3. Ограничения (constraints)3. Constraints

🌐 EN summary — Constraints enforce data integrity. Constraints are rules the DBMS checks automatically on every insert or update. A primary key uniquely identifies each row and cannot be NULL. A foreign key ensures a column only stores values that exist as a primary key in another table, preventing orphan records. NOT NULL requires a value, UNIQUE blocks duplicates (NULL allowed), CHECK validates a boolean condition and DEFAULT supplies a fallback value. If any rule is broken the operation is rejected, so constraints are the schema-level guarantee that bad data never enters the database.

Ограничения — это правила, которые СУБД сама проверяет при вставке или обновлении строки. Если правило нарушено — операция отменяется, и пользователь получает ошибку. Это важнейший инструмент целостности данных. Constraints are rules that the DBMS checks itself when a row is inserted or updated. If a rule is broken, the operation is cancelled and the user gets an error. This is the most important tool for data integrity.

4. SELECT — главный оператор4. SELECT — the main statement

🌐 EN summary — SELECT retrieves data. A query is an SQL instruction that extracts information from a database. The SELECT statement names the columns to return and FROM names the source table. Listing column names explicitly is preferred over SELECT * because it is faster and the output is more predictable. Queries can filter rows, perform pattern matching and sort results — and form the foundation that more advanced features (joins, aggregation, subqueries) extend. When data comes from a single table no join is needed; multiple tables require a join expression.

SELECT — самый важный оператор в SQL. Им мы извлекаем данные из таблиц. В IB-учебнике «запрос» (query) определяется как «инструкция на SQL для извлечения информации из БД». Запросы умеют: фильтровать (find), искать по образцу (pattern matching), сортировать данные. SELECT is the most important statement in SQL. We use it to retrieve data from tables. In the IB textbook, a query is defined as an SQL statement for retrieving information from a database. Queries can filter (find), search by pattern (pattern matching) and sort the data.

7. Агрегатные функции7. Aggregate functions

🌐 EN summary — Aggregate functions collapse rows into one value. Aggregate functions reduce many rows down to a single summary number. COUNT(*) returns the total number of rows including NULLs, while COUNT(column) counts only non-NULL values in that column. SUM adds numeric values and AVG computes the arithmetic mean. MIN and MAX return the smallest and largest value respectively. A key rule: aggregate functions cannot appear in WHERE — they belong in SELECT or HAVING. Combined with grouping, they answer questions like total revenue, average price or how many records exist per category.

Агрегатные функции сворачивают множество строк в одно значение — это A3.3.4 на экзамене. Главное правило: их нельзя использовать в WHERE, только в SELECT и в HAVING. Aggregate functions collapse a set of rows into one value — this is A3.3.4 on the exam. The main rule: they cannot be used in WHERE, only in SELECT and in HAVING.

8. GROUP BY и HAVING8. GROUP BY and HAVING

🌐 EN summary — GROUP BY buckets rows; HAVING filters those buckets. GROUP BY column collapses rows that share the same value of that column into one row per group, allowing aggregate functions to run per group rather than across the whole table. HAVING then filters those grouped results — it works on aggregate values, whereas WHERE filters individual rows before grouping. The full execution order for a query is FROM, then WHERE, then GROUP BY, then HAVING, then SELECT, then ORDER BY, then LIMIT. Remembering this pipeline explains why aggregates are blocked from WHERE.

8.1 GROUP BY — группируем строки8.1 GROUP BY — grouping rows

GROUP BY объединяет строки с одинаковым значением выбранного поля в одну «сводную». Применяется вместе с агрегатными функциями. GROUP BY combines rows with the same value of the chosen field into one "summary" row. It is used together with aggregate functions.

-- Сколько покупателей в каждой стране?
SELECT COUNT(CustomerID) AS Total, CustomerCountry
FROM Customer
GROUP BY CustomerCountry;-- How many customers are there in each country?
SELECT COUNT(CustomerID) AS Total, CustomerCountry

9. JOIN — объединяем таблицы9. JOIN — combining tables

🌐 EN summary — Joins combine rows from related tables. A join links rows from two tables on a shared field, typically a foreign key that references the primary key of the other table. INNER JOIN

Только строки, где есть совпадение в обеих таблицах.Only rows where there is a match in both tables.

Все строки правой таблицы + совпадения слева. Если слева нет — NULL.All rows of the right table, plus the matching rows on the left. If there is no match on the left, the result is NULL.

Все строки из обеих таблиц. Где нет пары — NULL.All rows from both tables. Where there is no match, the result is NULL.

10. Подзапросы (вложенный SELECT)10. Subqueries (nested SELECT)

🌐 EN summary — Subqueries nest one query inside another. A subquery is a SELECT statement embedded inside another SQL statement, often used when an intermediate value must be computed before the outer query can run. Подзапрос — это SELECT внутри другого SELECT (или UPDATE, DELETE). Применяют, когда нужно сначала вычислить промежуточное значение, а затем по нему отфильтровать или соединить данные. A subquery is a SELECT inside another SELECT (or UPDATE, DELETE). It is used when you first need to calculate an intermediate value, and then filter or join the data using it.

12. Транзакции и ACID12. Transactions and ACID

🌐 EN summary — Transactions and the ACID properties. A transaction is a group of SQL operations treated as one indivisible unit of work — either every step succeeds and is committed, or none of them take effect. BEGIN TRANSACTION starts the block, COMMIT makes changes permanent, and ROLLBACK undoes everything since the begin. The DBMS guarantees four properties known as ACID. Atomicity enforces all-or-nothing execution. Consistency ensures the database moves from one valid state to another, respecting all constraints. Isolation hides intermediate states from concurrent transactions. Durability guarantees that once committed, changes survive crashes by being written to persistent storage.

Это A3.3.6 на экзамене (AHL — Higher Level). Транзакция — это группа SQL-операций, которые СУБД выполняет как одно целое: либо все успешно, либо ни одной (как будто ничего не было). This is A3.3.6 on the exam (AHL — Higher Level). A transaction is a group of SQL operations that the DBMS carries out as one whole: either all of them succeed, or none of them (as if nothing had happened).

12.1 BEGIN, COMMIT, ROLLBACK

BEGIN TRANSACTION;            -- начали транзакцию

UPDATE Account
SET Balance = Balance - 100
WHERE AccountID = 1;          -- сняли 100$ со счёта А

UPDATE Account
SET Balance = Balance + 100
WHERE AccountID = 2;          -- зачислили 100$ на счёт Б

COMMIT;                       -- если оба прошли — фиксируем
-- или ROLLBACK; если что-то сломалосьBEGIN TRANSACTION;            -- start the transaction

UPDATE Account
SET Balance = Balance - 100
WHERE AccountID = 1;          -- withdraw 100$ from account A

UPDATE Account
SET Balance = Balance + 100
WHERE AccountID = 2;          -- deposit 100$ into account B

COMMIT;                       -- if both succeed — commit
-- or ROLLBACK; if something has gone wrong

COMMIT «застывает» изменения навсегда. ROLLBACK восстанавливает БД к состоянию до BEGIN — отменяет всё, что произошло внутри транзакции. COMMIT makes the changes permanent. ROLLBACK restores the database to its state before BEGIN — it cancels everything that happened inside the transaction.

12.2 Свойства ACID12.2 The ACID properties

Чтобы СУБД могла гарантировать корректность транзакций, она обеспечивает четыре свойства, аббревиатура — ACID: So that the DBMS can guarantee correct transactions, it provides four properties; the abbreviation is ACID:

A

Atomicity — АтомарностьAtomicity

«Всё или ничего». Если хоть одна операция в транзакции сломалась — отменяется вся транзакция. Не бывает «полупроведённой» сделки. Аналогия: перевод между счетами — нельзя списать у одного и не зачислить другому."All or nothing". If even one operation in a transaction fails, the whole transaction is cancelled. There is no such thing as a half-completed deal. Analogy: a transfer between accounts — you cannot take money from one account and not credit the other.

C

Consistency — СогласованностьConsistency

БД должна перейти из одного корректного состояния в другое. Все ограничения (PRIMARY KEY, FOREIGN KEY, CHECK) после транзакции остаются выполненными. Если транзакция нарушает правило — она откатится.The database must move from one correct state to another. All constraints (PRIMARY KEY, FOREIGN KEY, CHECK) remain satisfied after the transaction. If a transaction breaks a rule, it is rolled back.

I

Isolation — ИзолированностьIsolation

Параллельные транзакции не видят промежуточные состояния друг друга. Результат должен быть таким, как будто они шли по очереди — даже если на самом деле они шли параллельно.Concurrent transactions do not see each other's intermediate states. The result must be the same as if they had run one after another — even if in reality they ran in parallel.

D

Durability — ДолговечностьDurability

После COMMIT данные сохраняются надёжно — даже если сразу после этого сервер выключат из розетки. СУБД записывает изменения в журнал на диск.After COMMIT, the data is saved reliably — even if the server is unplugged right after that. The DBMS writes the changes to a log on disk.

💡 Как запомнить: «Атомарно, согласованно, изолированно, долговечно». Каждое свойство решает свою проблему: A — сбои внутри транзакции; C — нарушение правил БД; I — конфликты параллелизма; D — отказы оборудования после успеха. 💡 How to remember: each letter stands for a property: Atomicity, Consistency, Isolation, Durability. Each property solves its own problem: A — failures inside a transaction; C — breaking the rules of the database; I — conflicts of concurrent access; D — hardware failures after success.

Классический пример — банковский переводA classic example — a bank transfer

Перевод 100$ со счёта Алисы на счёт Боба. Без транзакции:A transfer of 100$ from Alice's account to Bob's account. Without a transaction:

  1. Снимаем 100$ у Алисы. Баланс: −100$.Withdraw 100$ from Alice. Balance: −100$.
  2. Сервер падает ⚡The server crashes ⚡
  3. Зачисление Бобу не произошло. 100$ пропали.The credit to Bob never happens. 100$ has disappeared.

С транзакцией (ACID):With a transaction (ACID):

  1. BEGIN TRANSACTION
  2. UPDATE Алиса −100$UPDATE Alice −100$
  3. Сервер падает ⚡The server crashes ⚡
  4. При перезапуске СУБД видит незавершённую транзакцию → автоматический ROLLBACK → баланс Алисы восстановлен.When the DBMS restarts, it sees the unfinished transaction → automatic ROLLBACK → Alice's balance is restored.

13. Представления (VIEW) и DCL13. Views (VIEW) and DCL

🌐 EN summary — Views and access control. A database view is a virtual table built from a stored SELECT query. The view itself contains no duplicated data — every time it is queried the underlying SELECT runs again against the base tables. Views simplify complex joins behind a friendly name, provide a security layer by exposing only chosen columns to certain users, and shield application code from schema changes. DCL handles permissions: GRANT gives a user or role specific privileges on an object, while REVOKE takes them back. Together, views and DCL implement the principle of least privilege.

13.1 Что такое VIEW13.1 What a VIEW is

Представление (view) — это виртуальная таблица, основанная на сохранённом SELECT-запросе. Физически данные не дублируются; каждый раз, когда обращаемся к view, СУБД на лету выполняет лежащий внутри запрос. A view is a virtual table based on a stored SELECT query. Physically, the data is not duplicated; each time we access the view, the DBMS runs the query it contains on the fly.

-- Создаём view: только активные товары с автором
CREATE VIEW ActiveItemsWithArtist AS
SELECT Item.ItemID, Item.ItemDesc, Item.ItemCost,
       Artist.ArtistName
FROM Item
INNER JOIN Artist ON Item.ArtistID = Artist.ArtistID
WHERE Item.Active = 1;

-- Теперь можно обращаться как к обычной таблице
SELECT * FROM ActiveItemsWithArtist WHERE ItemCost > 100;-- Create a view: only active items with their artist
CREATE VIEW ActiveItemsWithArtist AS
SELECT Item.ItemID, Item.ItemDesc, Item.ItemCost,
       Artist.ArtistName
FROM Item
INNER JOIN Artist ON Item.ArtistID = Artist.ArtistID
WHERE Item.Active = 1;

-- Now you can access it like an ordinary table

Зачем нужны viewsWhy we use views

  • Упрощение запросов: сложный JOIN прячется за коротким именем view.Simpler queries: a complex JOIN is hidden behind a short view name.
  • Безопасность: можно дать пользователю доступ только к view, а не к исходной таблице — он не увидит «лишние» колонки (например, зарплаты сотрудников).Security: you can give a user access only to the view, not to the original table — they will not see the "extra" columns (for example, staff salaries).
  • Совместимость: схема меняется, а view остаётся «фасадом» с привычной структурой.Compatibility: the schema changes, but the view remains a "facade" with the familiar structure.

13.2 DCL — GRANT и REVOKE13.2 DCL — GRANT and REVOKE

GRANT выдаёт пользователю права; REVOKE их забирает.GRANT gives a user privileges; REVOKE takes them away.

-- Дать пользователю librarian право только читать таблицу Book
GRANT SELECT ON Book TO librarian;

-- Дать админу полные права на всю БД
GRANT ALL PRIVILEGES ON school_db.* TO admin;

-- Забрать право на удаление
REVOKE DELETE ON Book FROM librarian;-- Give the user librarian the privilege to only read the Book table
GRANT SELECT ON Book TO librarian;

-- Give admin full privileges on the whole database
GRANT ALL PRIVILEGES ON school_db.* TO admin;

-- Take away the delete privilege
REVOKE DELETE ON Book FROM librarian;
