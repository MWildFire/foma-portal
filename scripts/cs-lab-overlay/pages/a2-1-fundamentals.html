🌐 1. A2.1.1 — Типы сетей: LAN, WAN, PAN, VPN🌐 1. A2.1.1 — Types of network: LAN, WAN, PAN, VPN

Существует много разных типов сетей, и каждый создан под свою задачу. Сети могут иметь похожие черты, но цели у них совершенно разные. На экзамене нужно уметь определить три ключевые характеристики любой сети: географический охват (distance), скорость передачи данных (transfer rate) и задержка (latency). There are many different types of network, and each is designed for its own purpose. Networks can have similar features, but their purposes are completely different. In the exam you must be able to identify three key characteristics of any network: geographical scope, data transfer rate and latency.

🏢 A. Local Area Network (LAN) — локальная сеть🏢 A. Local area network (LAN)

НазначениеPurpose
Соединяет устройства на коротком расстоянии — обычно не больше ~1 километра.Connects devices over a short distance — usually no more than about 1 kilometre.
ХарактеристикиCharacteristics
  • Высокая скорость передачи данных (high data transfer rate).High data transfer rate.
  • Низкая задержка (low latency) — потому что устройства физически близко.Low latency — because the devices are physically close.
  • Может быть проводной, беспроводной или смешанной (обычно смесь).Can be wired, wireless or mixed (usually a mix).
Главная цельMain purpose
Совместное использование ресурсов — файлов, принтеров, программ — несколькими пользователями в одной местности.Sharing resources — files, printers, software — between several users in the same area.
ПримерыExamples
Школа, университетский кампус, офисное здание, больница, гостиница, ресторан.School, university campus, office building, hospital, hotel, restaurant.

🗺️ B. Wide Area Network (WAN) — глобальная (территориальная) сеть🗺️ B. Wide area network (WAN)

НазначениеPurpose
Соединяет устройства на больших географических расстояниях — между городами, странами и даже континентами.Connects devices over large geographical distances — between cities, countries and even continents.
ХарактеристикиCharacteristics
  • Сохраняет связь на очень больших расстояниях.Maintains connections over very long distances.
  • Скорость обычно ниже, чем у LAN, а задержка выше.Speed is usually lower than in a LAN, and latency is higher.
  • Часто строится из множества меньших сетей (LAN/MAN), объединённых в единую систему.Often built from many smaller networks (LANs/MANs) joined into one system.
Главная цельMain purpose
Дать бизнесу, государству и другим организациям возможность работать в широком масштабе: централизованная обработка данных, совместная работа, общий доступ к ресурсам независимо от местоположения.Allow businesses, governments and other organisations to work on a large scale: centralised data processing, collaborative work and shared access to resources regardless of location.
Как строитсяHow it is built
  • Выделенные линии (leased lines) — постоянное подключение с фиксированной полосой пропускания, эксклюзивно для одного клиента; стабильная скорость, низкая задержка, надёжность.Leased lines — a permanent connection with fixed bandwidth, exclusive to one customer; stable speed, low latency, reliability.
  • Спутниковые каналы.Satellite links.
  • Публичный интернет с VPN для безопасности и приватности.The public internet with a VPN for security and privacy.
  • Физика: оптоволокно, медные кабели, радиосвязь — в зависимости от расстояния и местности.Physical media: optical fibre, copper cables, radio links — depending on distance and terrain.
ПримерыExamples
Транснациональные корпорации, соединяющие офисы по миру; государственные сервисы с централизованной базой данных для граждан в разных регионах.Multinational companies connecting their offices around the world; government services with a centralised database for citizens in different regions.

📱 C. Personal Area Network (PAN) — персональная сеть📱 C. Personal area network (PAN)

НазначениеPurpose
Спроектирована для личного использования, охват обычно не больше 10 метров (примерно 30 футов) — рабочее место одного человека или его непосредственное окружение.Designed for personal use, with a range of usually no more than 10 metres (about 30 feet) — one person’s workspace or their immediate surroundings.
ХарактеристикиCharacteristics
  • Маленький масштаб — связь именно между личными гаджетами одного пользователя.Small scale — connections only between one user’s personal devices.
  • Удобство и быстрая синхронизация устройств.Convenient and fast synchronisation of devices.
  • Обычно беспроводная и с низким энергопотреблением.Usually wireless and low-power.
Главная цельMain purpose
Связать персональные устройства, упростить обмен данными и личными ресурсами (контакты, доступ в интернет, мультимедиа).Connect personal devices and make it easier to share data and personal resources (contacts, internet access, multimedia).
ТехнологииTechnologies
Bluetooth, Wi-Fi Direct — оба специально разработаны под короткие расстояния и низкое потребление.Bluetooth, Wi-Fi Direct — both are designed specifically for short distances and low power consumption.
ПримерыExamples
  • Смартфон + умные часы (фитнес) + беспроводные наушники (музыка).Smartphone + smartwatch (fitness) + wireless headphones (music).
  • Ноутбук + беспроводная мышь и клавиатура.Laptop + wireless mouse and keyboard.
  • Планшет выходит в интернет через мобильные данные смартфона (tethering).A tablet gets internet access through the smartphone’s mobile data (tethering).

🔐 D. Virtual Private Network (VPN) — виртуальная частная сеть🔐 D. Virtual private network (VPN)

НазначениеPurpose
«Расширяет» частную сеть через публичную сеть (через интернет) так, как будто твоё устройство напрямую подключено к частной сети.Extends a private network over a public network (the internet), so that your device works as if it were connected directly to the private network.
ХарактеристикиCharacteristics
  • Может работать на неограниченном расстоянии — поверх интернета.Can operate over unlimited distance — on top of the internet.
  • Создаёт безопасный зашифрованный «туннель» между устройством и частной сетью.Creates a secure, encrypted “tunnel” between the device and the private network.
  • Шифрование гарантирует, что данные защищены от несанкционированного доступа.Encryption ensures that data is protected from unauthorised access.
Главная цельMain purpose
Безопасный удалённый доступ к частной сети и её ресурсам (файлы, принтеры, приложения) из любого места с интернетом.Secure remote access to a private network and its resources (files, printers, applications) from anywhere with an internet connection.
Примеры использованияExamples of use
  • Сотрудник из дома подключается к внутренним серверам и документам компании.An employee at home connects to the company’s internal servers and documents.
  • Приватный сёрфинг — без раскрытия настоящего IP-адреса и местоположения.Private browsing — without revealing the real IP address and location.
  • Доступ к гео-ограниченному контенту — выглядишь как пользователь из другой страны.Access to geo-restricted content — you appear to be a user from another country.
РеализацияImplementation
Программное ПО на ноутбуках/смартфонах/планшетах или настройка на маршрутизаторе, чтобы защитить весь трафик локальной сети сразу.Software on laptops, smartphones or tablets, or a configuration on a router to protect all the traffic of the local network at once.

VPN — это не отдельный тип сети по железу, а способ построить «частную» сеть поверх публичной, поэтому его географический охват = охват интернета. 💡 Tip: remember the distance limits — PAN ≈ 10 m, LAN ≈ 1 km, WAN — no upper limit. A VPN is not a separate type of network by hardware, but a way to build a “private” network over a public one, so its geographical scope equals the scope of the internet.

☁️ 2. A2.1.2 — Современная цифровая инфраструктура☁️ 2. A2.1.2 — Modern digital infrastructure

«Инфраструктура» — это базовые физические и виртуальные компоненты, которые обеспечивают работу и движение цифровых данных по сети. Это «дороги, мосты и развязки», по которым ездят «пакеты данных». В современную инфраструктуру входят: интернет, облачные вычисления, распределённые системы, edge-вычисления, fog-вычисления и мобильные сети. “Infrastructure” is the set of basic physical and virtual components that support the operation and movement of digital data across the network. They are like “roads, bridges and junctions” along which “data packets” travel. Modern infrastructure includes the internet, cloud computing, distributed systems, edge computing, fog computing and mobile networks.

🌍 A. Интернет (The Internet)🌍 A. The Internet

Что этоWhat it is
Глобальная сеть взаимосвязанных устройств (маршрутизаторы, серверы, компьютеры), которые обмениваются данными по стандартизированным протоколам. WWW — это инфраструктура поверх интернета, использующая HTTP.A global network of interconnected devices (routers, servers, computers) that exchange data using standardised protocols. The WWW is an infrastructure on top of the internet that uses HTTP.
Главная цельMain purpose
Обеспечить надёжный, устойчивый к сбоям глобальный обмен данными и коммуникацию.Provide reliable, fault-tolerant global data exchange and communication.

Плюсы (benefits)Benefits

  • Глобальная связь и сотрудничество.Global communication and collaboration.
  • Огромные объёмы текстовых, видео- и аудиоданных.Allows huge volumes of text, video and audio data to be exchanged.
  • Лучшее общение с клиентами и партнёрами; снижение издержек; получение инсайтов о клиентах.Better communication with customers and partners; lower costs; insights into customers.
  • Делает возможным онлайн-образование и виртуальное обучение.Makes online education and virtual learning possible.

Минусы / ограниченияDrawbacks / limitations

  • Полоса пропускания сильно зависит от географии, перегруженности и качества инфраструктуры.Bandwidth depends heavily on geography, congestion and the quality of the infrastructure.
  • Должен развиваться, чтобы тянуть рост объёмов данных без деградации качества.It must keep developing to cope with growing data volumes without a loss of quality.
  • Уязвимости создают риски для личной, организационной и национальной безопасности.Vulnerabilities create risks for personal, organisational and national security.
  • Чем больше критической инфраструктуры подключено к интернету, тем выше требования к безопасности и надёжности.The more critical infrastructure is connected to the internet, the higher the requirements for security and reliability.

☁️ B. Облачные вычисления (Cloud computing)☁️ B. Cloud computing

Что этоWhat it is
Сеть удалённых серверов, доступная через интернет, для хранения, обработки и управления данными. Также — программы как сервис: пользователь работает через браузер, без локальной установки.A network of remote servers, available over the internet, for storing, processing and managing data. It also means software as a service: the user works through a browser, without local installation.
Главная цельMain purpose
Дать масштабируемый доступ по запросу к вычислительным ресурсам и сервисам.Provide scalable on-demand access to computing resources and services.
Модели сервисаService models
  • SaaS (Software as a Service) — готовое ПО через браузер. Пример: Google Docs, Office 365.SaaS (Software as a Service) — ready-made software used through a browser. Example: Google Docs, Office 365.
  • PaaS (Platform as a Service) — платформа для разработки и развёртывания приложений без управления серверами. Пример: Heroku, Google App Engine.PaaS (Platform as a Service) — a platform for developing and deploying applications without managing servers. Example: Heroku, Google App Engine.
  • IaaS (Infrastructure as a Service) — аренда виртуальных серверов, сетей и хранилищ. Пример: AWS EC2, Azure VM.IaaS (Infrastructure as a Service) — renting virtual servers, networks and storage. Example: AWS EC2, Azure VM.

ПлюсыBenefits

  • Масштабируется вверх и вниз по требованию — платишь только за то, что используешь.Scales up and down on demand — you pay only for what you use.
  • Доступ к данным из любой точки, в любое время — удобство для распределённых команд.Access to data from any place, at any time — convenient for distributed teams.
  • Резервное копирование и аварийное восстановление от провайдера — целостность данных и минимум простоя.Backup and disaster recovery from the provider — data integrity and minimal downtime.
  • Школы экономят на покупке и поддержке серверов — подписка дешевле собственного железа.Schools save money on buying and maintaining servers — a subscription is cheaper than their own hardware.

МинусыDrawbacks

  • Нужен надёжный интернет; при сбое связи нет доступа к данным.Needs a reliable internet connection; if the connection fails, there is no access to the data.
  • Хранение чувствительных данных вне организации — вопросы безопасности, приватности и соответствия требованиям регуляторов.Storing sensitive data outside the organisation raises questions of security, privacy and compliance with regulators’ requirements.
  • Большие объёмы передачи данных дорого стоят.Large volumes of data transfer are expensive.
  • Полоса пропускания ограничивает производительность при работе с большими данными.Bandwidth limits performance when working with large amounts of data.
  • Физическое расстояние до серверов создаёт задержку, что критично для real-time приложений.The physical distance to the servers creates latency, which is critical for real-time applications.

🕸️ C. Распределённые системы (Distributed systems)🕸️ C. Distributed systems

Что этоWhat it is
Сеть независимых компьютеров, которая для пользователя выглядит как единая связная система. Компьютеры внутри называются узлами (nodes). Узлы координируют действия, обмениваясь сообщениями. Чем больше узлов — тем мощнее ресурс.A network of independent computers that appears to the user as a single coherent system. The computers inside are called nodes. The nodes coordinate their actions by exchanging messages. The more nodes, the more powerful the resource.
КонфигурацииConfigurations
  • Централизованная (centralized) — все обращаются к одной центральной станции.Centralised — all clients access one central station.
  • Децентрализованная (decentralized) — несколько крупных узлов, у каждого свои клиенты.Decentralised — several large nodes, each with its own clients.
  • Распределённая (distributed) — без явного центра, узлы общаются между собой произвольно.Distributed — no fixed centre; nodes communicate with each other as needed.
Главная цельMain purpose
Координировать и распределять процессы и ресурсы между несколькими компьютерами, чтобы они работали вместе эффективнее и надёжнее, чем мог бы один компьютер.Coordinate and share out processes and resources among several computers, so that they work together more efficiently and reliably than one computer could.
Реальный примерReal example
Apache Hadoop — фреймворк для распределённого хранения и обработки больших данных. Масштабируется от одного сервера до тысяч машин; добавление узлов прямо повышает вычислительную мощность, ёмкость хранилища и отказоустойчивость.Apache Hadoop — a framework for distributed storage and processing of big data. It scales from one server to thousands of machines; adding nodes directly increases computing power, storage capacity and fault tolerance.

ПлюсыBenefits

  • Совместное использование ресурсов; выше вычислительная скорость за счёт распараллеливания задач.Shared use of resources; higher computing speed through parallel processing of tasks.
  • Надёжность: если один компонент падает, остальная система продолжает работать.Reliability: if one component fails, the rest of the system keeps working.
  • Гибкое и эффективное расширение под рост нагрузки.Flexible and efficient scaling as the load grows.

МинусыDrawbacks

  • Сложно обеспечить надёжную связь и координацию по нестабильным сетям.It is hard to ensure reliable communication and coordination over unstable networks.
  • Проблемы согласованности данных (consistency) и параллелизма (concurrency control) при репликации.Problems with data consistency and concurrency control when data is replicated.
  • Шире поверхность атаки: данные ходят по публичным сетям и хранятся на многих машинах.A wider attack surface: data travels over public networks and is stored on many machines.
  • Распределённая природа может вносить задержку и снижать производительность отдельных операций.The distributed nature can add delay and reduce the performance of individual operations.
  • Требуются сложные алгоритмы для обработки сбоев, целостности и безопасности.Complex algorithms are needed to handle failures, integrity and security.

📡 D. Edge-вычисления (Edge computing)📡 D. Edge computing

Что этоWhat it is
Обработка данных прямо у источника (или близко к нему), а не на удалённом центральном облаке. Сокращает расстояние, которое данные должны пройти — быстрее ответ, меньше задержка, особенно важно для приложений реального времени.Processing data right at the source (or close to it), rather than in a remote central cloud. It reduces the distance the data has to travel — faster response, less latency, which is especially important for real-time applications.
Главная цельMain purpose
Приблизить обработку данных к месту их генерации, снизить зависимость от центрального дата-центра, ускорить отклик, сэкономить трафик.Bring data processing closer to where the data is generated, reduce dependence on the central data centre, speed up response and save traffic.
ПримерыExamples
  • Умные светофоры: датчики собирают данные о потоке машин и тут же меняют тайминг светофора — не нужно ждать ответа из удалённого ЦОД.Smart traffic lights: sensors collect data on the flow of cars and immediately change the timing of the light — there is no need to wait for a reply from a remote data centre.
  • Распознавание автомобильных номеров: камера обрабатывает видео локально и отправляет уже распознанный номер, а не сырой видеопоток.Number plate recognition: the camera processes the video locally and sends the already recognised number plate, not the raw video stream.
  • Беспилотные автомобили, IoT-устройства.Self-driving cars, IoT devices.

ПлюсыBenefits

  • Быстрая обработка и низкая задержка — идеально для real-time.Fast processing and low latency — ideal for real-time use.
  • Меньше данных уходит в облако → экономия трафика и денег.Less data goes to the cloud → savings in bandwidth and money.
  • Локальная обработка продолжается даже при обрыве связи с центральным сервером — выше надёжность.Local processing continues even when the connection to the central server is lost — higher reliability.
  • Чувствительные данные могут остаться на месте, уменьшая риски при передаче.Sensitive data can stay on site, reducing the risks of transmission.

МинусыDrawbacks

  • Управление множеством распределённых edge-устройств — сложно, нужна автоматизация.Managing many distributed edge devices is difficult and needs automation.
  • Безопасность — двусмысленна: данные локальные, но устройств много, каждое — потенциальная мишень.Security is ambiguous: the data is local, but there are many devices, and each one is a potential target.
  • Высокие первоначальные и операционные расходы — нужно железо в каждой точке.High initial and operating costs — hardware is needed at every site.
  • Несогласованность характеристик у разных edge-устройств — разная производительность.Inconsistent characteristics across different edge devices — varying performance.

🌫️ E. Fog-вычисления (Fog computing)🌫️ E. Fog computing

Fog computing — это «промежуточный слой» между облаком и устройствами на самой границе (edge). Если edge — это сам датчик или камера, то fog — это узлы немного выше: локальные серверы, шлюзы, маршрутизаторы внутри корпоративной сети, которые принимают данные с edge-устройств, обрабатывают, фильтруют и только важное отправляют в облако. Fog computing is an “intermediate layer” between the cloud and devices at the very edge. If the edge is the sensor or camera itself, the fog is the nodes a little higher up: local servers, gateways and routers inside a corporate network. They receive data from edge devices, process and filter it, and send only the important data to the cloud.

Связка edge + fog + cloudEdge + fog + cloud
  • Edge — на самом устройстве (датчик, камера, светофор).Edge — on the device itself (sensor, camera, traffic light).
  • Fog — на локальном узле в пределах сети (шлюз умного дома, локальный сервер фабрики).Fog — on a local node within the network (smart home gateway, factory local server).
  • Cloud — в удалённом дата-центре.Cloud — in a remote data centre.
Зачем нужен fogWhy fog is needed
Снижает задержку и нагрузку на канал сильнее, чем чистое облако, но даёт больше вычислительной мощности и хранения, чем маломощное edge-устройство.It reduces latency and the load on the link more than a pure cloud does, but gives more computing power and storage than a low-powered edge device.
ПримерExample
Умное здание: тысячи датчиков (edge) шлют данные на локальный сервер здания (fog), который усредняет, агрегирует и отправляет в облако только сводки по часам.A smart building: thousands of sensors (edge) send data to the building’s local server (fog), which averages and aggregates it and sends only hourly summaries to the cloud.

📦 4. A2.1.4 — Сетевые протоколы📦 4. A2.1.4 — Network protocols

Протокол — это набор правил и стандартов, который определяет, как данные должны быть структурированы, переданы и получены через сеть. Протоколы задают формат, тайминг, последовательность и проверку ошибок при передаче. A protocol is a set of rules and standards that defines how data must be structured, sent and received over a network. Protocols specify the format, timing, sequencing and error checking of transmission.

Протоколы бывают с состоянием (stateful) и без состояния (stateless): Protocols can be stateful and stateless:

  • Stateful — сервер помнит информацию о сессии клиента между запросами (TCP, FTP, SMTP).Stateful — the server remembers information about the client’s session between requests (TCP, FTP, SMTP).
  • Stateless — каждый запрос обрабатывается независимо, сервер ничего не помнит (HTTP, UDP, DNS). Чтобы поддерживать «состояние» (например, корзину в магазине), нужны cookies или похожие механизмы.Stateless — each request is handled independently and the server remembers nothing (HTTP, UDP, DNS). To maintain a “state” (for example, a shopping basket in a web shop), cookies or similar mechanisms are needed.

  • Результат сохраняется в ARP-кэше, чтобы не спрашивать каждый раз.The result is stored in the ARP cache, so the device does not have to ask every time.
ЗачемWhy it matters
Внутри LAN кадры доставляются по MAC (на канальном уровне), а приложения работают с IP — ARP «склеивает» два мира.Inside a LAN, frames are delivered by MAC address (at the link layer), while applications work with IP addresses — ARP links the two worlds together.

🧱 5. A2.1.5 — Модель TCP/IP HL🧱 5. A2.1.5 — The TCP/IP model HL

Цифровые сети — сложные, взаимозависимые системы с разными устройствами, протоколами, средами передачи и потенциальными проблемами. Чтобы упростить понимание, отладку и стандартизацию, используют концептуальные модели. Самая известная — TCP/IP model с четырьмя уровнями. Digital networks are complex, interdependent systems with different devices, protocols, transmission media and potential problems. To simplify understanding, troubleshooting and standardisation, conceptual models are used. The best known is the TCP/IP model with four layers.

На каждом уровне с сообщением что-то происходит, прежде чем оно передаётся на следующий уровень. При отправке данные идут сверху вниз, при получении — снизу вверх. At each layer, something happens to the message before it is passed to the next layer. When sending, data travels from top to bottom; when receiving, it travels from bottom to top.

Пошаговый пример: пользователь открывает веб-страницуStep-by-step example: a user opens a web page

Это классический сценарий, который надо знать наизусть для HL-экзамена. Идём по 8 шагам. This is a classic scenario that you should know by heart for the HL exam. We go through the 8 steps.

1️⃣ Шаг 1. Application layer — пользователь запрашивает страницу1️⃣ Step 1. Application layer — the user requests the page

  • Пользователь вводит URL и нажимает Enter.The user types the URL and presses Enter.
  • Браузер на прикладном уровне строит HTTP GET запрос для получения страницы — по правилам протокола HTTP.At the application layer, the browser builds an HTTP GET request to fetch the page — following the rules of the HTTP protocol.
  • Запрос передаётся вниз — на транспортный уровень.The request is passed down to the transport layer.

2️⃣ Шаг 2. Transport layer — подготовка к передаче2️⃣ Step 2. Transport layer — preparing for transmission

  • HTTP-запрос превращается в TCP-сегмент. Добавляется TCP-заголовок: номер последовательности, порт источника и назначения (HTTP — порт 80, HTTPS — порт 443), контрольная сумма.The HTTP request becomes a TCP segment. A TCP header is added: sequence number, source and destination port (HTTP — port 80, HTTPS — port 443), checksum.
  • УстанавливаетсяSet up a TCP-соединение через 3-way handshakeTCP connection through a 3-way handshake:
    • SYN — клиент: «Привет, я хочу поговорить, ты готов?»SYN — client: “Hi, I want to talk. Are you ready?”
    • SYN-ACK — сервер: «Ок, получил, я готов слушать».SYN-ACK — server: “OK, received. I am ready to listen.”
    • ACK — клиент: «Отлично, начинаю слать данные!»ACK — client: “Great, I am starting to send data!”
  • После handshake соединение установлено, сегмент уходит вниз на интернет-уровень. Если handshake провалился, пакет не пойдёт дальше — пользователь увидит «connection timed out».After the handshake the connection is established and the segment goes down to the internet layer. If the handshake fails, the packet does not go any further — the user sees “connection timed out”.

3️⃣ Шаг 3. Internet layer — упаковка для маршрутизации3️⃣ Step 3. Internet layer — packaging for routing

  • TCP-сегмент инкапсулируется в IP-пакет. Добавляется IP-заголовок: IP источника, IP назначения, тип данных (тут — TCP), TTL (time to live) и checksum для заголовка.The TCP segment is encapsulated in an IP packet. An IP header is added: the source IP, the destination IP, the type of data (here TCP), the TTL (time to live) and a header checksum.
  • Пакет получает next hop — обычно адрес маршрутизатора в твоей локальной сети.The packet gets a next hop — usually the address of the router in your local network.
  • Пакет передаётся вниз — на канальный уровень.The packet is passed down to the network interface layer.

4️⃣ Шаг 4. Network interface layer — финальная упаковка и сигнал4️⃣ Step 4. Network interface layer — final packaging and signal

  • IP-пакет инкапсулируется в Ethernet-кадр (если сеть Ethernet). Кадр содержит MAC источника, MAC получателя (следующего хопа), управляющую информацию и checksum.The IP packet is encapsulated in an Ethernet frame (if the network is Ethernet). The frame contains the source MAC, the destination MAC (of the next hop), control information and a checksum.
  • NIC (Network Interface Card) преобразует кадр в электрические сигналы (или световые импульсы для оптоволокна, или радиоволны для Wi-Fi).The NIC (Network Interface Card) converts the frame into electrical signals (or light pulses for optical fibre, or radio waves for Wi-Fi).
  • Сигналы передаются по физической среде — медный кабель, оптоволокно, Wi-Fi.The signals travel over the physical medium — copper cable, optical fibre, Wi-Fi.
  • На этом уровне всё становится зависимо от конкретной физической сети.At this layer everything depends on the specific physical network.

🌍 Между шагами 4 и 5 — путешествие через интернет🌍 Between steps 4 and 5 — the journey across the internet

Кадр идёт через интернет, прыгая через множество маршрутизаторов. Каждый маршрутизатор смотрит на IP назначения и определяет следующий хоп. На каждом хопе MAC-адреса меняются (новый отправитель, новый получатель — следующий маршрутизатор), но IP-адреса источника и назначения остаются прежними.The frame travels across the internet, hopping through many routers. Each router looks at the destination IP and determines the next hop. At each hop the MAC addresses change (a new sender and a new recipient — the next router), but the source and destination IP addresses stay the same.

5️⃣ Шаг 5. Получение на сервере — снизу вверх5️⃣ Step 5. Receiving at the server — from bottom to top

  • Network interface: NIC сервера получает сигналы, преобразует обратно в кадр. Проверяет checksum, проверяет MAC-адрес назначения. Снимает Ethernet-заголовок и trailer, передаёт пакет наверх.Network interface: the server’s NIC receives the signals and converts them back into a frame. It checks the checksum and the destination MAC address. It removes the Ethernet header and trailer and passes the packet up.
  • Internet layer: сервер проверяет, что IP-назначения = его собственному IP. Проверяет checksum заголовка. Снимает IP-заголовок, передаёт TCP-сегмент наверх.Internet layer: the server checks that the destination IP is its own IP address. It checks the header checksum. It removes the IP header and passes the TCP segment up.
  • Transport layer: по номеру порта направляет данные нужному приложению (порт 80 = веб-сервер). Если запрос состоял из нескольких сегментов — собирает их в правильном порядке по номерам последовательности. Проверяет checksum. Передаёт целый HTTP GET приложению.Transport layer: using the port number, it directs the data to the right application (port 80 = web server). If the request was split into several segments, it puts them back in the correct order using the sequence numbers. It checks the checksum. It passes the whole HTTP GET to the application.

6️⃣ Шаг 6. Сервер отвечает6️⃣ Step 6. The server replies

  • Application: веб-сервер формирует HTTP response с HTML-содержимым страницы.Application: the web server creates an HTTP response with the page’s HTML content.
  • Transport: ответ упаковывается в TCP-сегменты, добавляются TCP-заголовки, сегменты отправляются клиенту.Transport: the response is packed into TCP segments, TCP headers are added, and the segments are sent to the client.
  • Internet: сегменты инкапсулируются в IP-пакеты.Internet: the segments are encapsulated in IP packets.
  • Network interface: пакеты упаковываются в кадры, превращаются в сигналы — и в путь обратно.Network interface: the packets are packed into frames, turned into signals — and sent on the way back.

7️⃣ Шаг 7. Клиент получает страницу7️⃣ Step 7. The client receives the page

  • Network interface: NIC клиента получает сигналы → кадр → проверка → пакет наверх.Network interface: the client’s NIC receives the signals → frame → check → packet up.
  • Internet: проверка IP, снятие IP-заголовка, передача TCP-сегмента наверх.Internet: IP check, removal of the IP header, passing the TCP segment up.
  • Transport: проверка checksum, сборка сегментов по порядку, передача HTTP-ответа приложению.Transport: checksum check, reassembly of the segments in order, passing the HTTP response to the application.
  • Application: браузер интерпретирует HTML и показывает страницу пользователю.Application: the browser interprets the HTML and shows the page to the user.

8️⃣ Шаг 8. Завершение соединения8️⃣ Step 8. Closing the connection

  • После успешной передачи TCP-соединение корректно закрывается.After a successful transfer, the TCP connection is closed properly.
  • FIN — сторона говорит «я закончил отправку, хочу закрыть соединение в эту сторону».FIN — one side says “I have finished sending; I want to close the connection in this direction”.
  • ACK — другая сторона подтверждает.ACK — the other side confirms.
  • Соединение разрывается «вежливо», без потерь данных.The connection is closed “politely”, without data loss.

Модель TCP/IP vs модель OSIThe TCP/IP model vs the OSI model

На экзамене иногда сравнивают TCP/IP с моделью OSI (Open Systems Interconnection) — это другая, более «академическая» концептуальная модель, у которой 7 уровней вместо 4. In the exam you may be asked to compare TCP/IP with the OSI (Open Systems Interconnection) model — a different, more “academic” conceptual model with 7 layers instead of 4.

Ключевые отличия: Key differences:

  • Количество уровней: OSI — 7, TCP/IP — 4.Number of layers: OSI — 7, TCP/IP — 4.
  • TCP/IP объединяет верхние три уровня OSI (Application, Presentation, Session) в один Application; нижние два уровня OSI (Data Link, Physical) объединены в один Network Interface.TCP/IP combines the top three OSI layers (Application, Presentation, Session) into one Application layer; the bottom two OSI layers (Data Link, Physical) are combined into one Network Interface layer.
  • OSI — теоретическая модель, часто используется для обучения и анализа.OSI is a theoretical model, often used for teaching and analysis.
  • TCP/IP — практическая, на ней реально построен интернет.TCP/IP is a practical model on which the internet is actually built.
  • Оба иерархические и используют инкапсуляцию: каждый уровень добавляет свой заголовок при отправке и снимает его при приёме.Both are hierarchical and use encapsulation: each layer adds its own header when sending and removes it when receiving.

📌 Что важно запомнить📌 Key points to remember

  • Типы сетей запоминай через расстояние: PAN ≈ 10 м, LAN ≈ 1 км, WAN — города/страны. VPN — это не отдельная сеть по железу, а зашифрованный туннель поверх интернета.Remember network types by distance: PAN ≈ 10 m, LAN ≈ 1 km, WAN — cities/countries. A VPN is not a separate network by hardware, but an encrypted tunnel over the internet.
  • VPN ≠ просто анонимность. Главная цель — безопасный удалённый доступ к частной сети.A VPN is not just about anonymity. Its main purpose is secure remote access to a private network.
  • У каждого типа инфраструктуры свой trade-off: облако = удобство против задержки и зависимости от связи; edge = скорость и автономность против сложности и стоимости; распределённые системы = мощность и отказоустойчивость против сложности согласованности.Each type of infrastructure has its own trade-off: cloud = convenience against latency and dependence on the connection; edge = speed and autonomy against complexity and cost; distributed systems = power and fault tolerance against the complexity of consistency.
  • SaaS/PaaS/IaaS: чем выше уровень (IaaS → SaaS), тем меньше управляешь, тем больше используешь готового.SaaS/PaaS/IaaS: the higher the level (IaaS → SaaS), the less you manage and the more ready-made services you use.
  • TCP vs UDP — самый частый вопрос: TCP даёт надёжность через handshake, acks, sequencing, flow control; UDP даёт скорость через отсутствие соединения и проверок. Когда важна целостность (веб, почта, файлы) — TCP. Когда важна скорость и непрерывность (стриминг, игры, VoIP, DNS) — UDP.TCP vs UDP — the most common question: TCP gives reliability through the handshake, acks, sequencing, flow control; UDP gives speed through the absence of a connection and checks. When integrity matters (web, email, files) — use TCP. When speed and continuity matter (streaming, games, VoIP, DNS) — use UDP.
  • HTTP — stateless и без шифрования; HTTPS — то же + TLS (шифрование). Stateless значит, что нужны cookies для поддержания сессии.HTTP is stateless and unencrypted; HTTPS is the same + TLS (encryption). Stateless means that cookies are needed to maintain a session.
  • DNS = имя → IP. DHCP = автоматическая раздача IP + настроек. Не путать.DNS = name → IP. DHCP = automatic allocation of IP + settings. Do not confuse them.
  • ARP — отвечает на вопрос «у кого этот IP в моей локальной сети?» и возвращает MAC. Работает только внутри LAN.ARP — answers the question “who has this IP in my local network?” and returns the MAC address. It works only inside a LAN.
  • 4 уровня TCP/IP сверху вниз (HL): Application → Transport → Internet → Network Interface. При отправке — сверху вниз, при получении — снизу вверх. На каждом уровне — инкапсуляция: добавляется заголовок со своими данными.The 4 TCP/IP layers from top to bottom (HL): Application → Transport → Internet → Network Interface. When sending — top to bottom, when receiving — bottom to top. At each layer — encapsulation: a header with its own data is added.
  • Знай 3-way handshake (SYN, SYN-ACK, ACK) и корректное закрытие (FIN, ACK) — это обязательно для HL.Know the 3-way handshake (SYN, SYN-ACK, ACK) and the orderly closing (FIN, ACK) — this is essential for HL.
  • Сравнение TCP/IP с OSI: у OSI 7 уровней, у TCP/IP 4. TCP/IP — практический стандарт, OSI — теоретическая модель. Application у TCP/IP = Application + Presentation + Session у OSI; Network Interface у TCP/IP = Data Link + Physical у OSI.Comparing TCP/IP with OSI: OSI has 7 layers, TCP/IP has 4. TCP/IP is a practical standard, OSI is a theoretical model. The TCP/IP Application layer = the OSI Application + Presentation + Session layers; the TCP/IP Network Interface layer = the OSI Data Link + Physical layers.
  • Послойный подход = разделение ответственности + стандартизация + инкапсуляция + контроль ошибок на каждом уровне + гибкость замены протоколов = надёжность всей сетевой коммуникации.The layered approach = separation of responsibilities + standardisation + encapsulation + error checking at each layer + flexibility to replace protocols = reliability of all network communication.
