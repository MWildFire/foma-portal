## Суть

Реальные программы состоят из многих классов, и эти классы зависят друг от друга. Объектно-ориентированное проектирование использует <Term id="b3-2-inheritance"/>, чтобы разделять общий код, <Term id="b3-2-polymorphism"/>, чтобы один вызов метода работал с разными видами объектов, <Term id="b3-2-abstraction"/>, чтобы прятать детали за общим описанием, и <Term id="b3-2-class-relationship"/>, чтобы показать, как классы связаны между собой.

## Объяснение

**Наследование.** <Term id="b3-2-inheritance"/> позволяет подклассу использовать атрибуты и методы суперкласса. Общий код пишется один раз в суперклассе, а каждый подкласс добавляет только то, что его отличает. В Python связь записывается в строке класса, например `class Student(Person):`, а `super().__init__()` запускает конструктор суперкласса. Изменение, сделанное в суперклассе, действует на все подклассы.

**Видимость.** Приватный атрибут (в Python — два символа подчёркивания в начале имени) виден только внутри своего класса, поэтому подкласс должен читать его через публичный геттер. Защищённый атрибут могут использовать подклассы, а публичный — любой код.

**Полиморфизм и переопределение.** <Term id="b3-2-polymorphism"/> означает, что у одного имени метода может быть много форм. Статический полиморфизм выбирает версию по параметрам; это называют перегрузкой методов (method overloading), а в Python перегрузки в стиле Java нет. Динамический полиморфизм показан в <Term id="b3-2-method-overriding"/>: метод подкласса с тем же именем заменяет версию суперкласса, когда метод вызывается у объекта подкласса. Статические методы переопределить нельзя.

**Утиная типизация.** В Python действует <Term id="b3-2-duck-typing"/>, поэтому важнее то, какие методы есть у объекта, а не его класс. Вызов `item.speak()` работает для любого объекта, у которого есть метод `speak()`. Если метода нет, ошибка появляется только тогда, когда выполняется эта строка.

**Абстракция.** <Term id="b3-2-abstraction"/> скрывает детали, которые пользователю не нужны. <Term id="b3-2-abstract-class"/> объявляет абстрактные методы без кода, из него нельзя создать объекты, и он гарантирует, что каждый подкласс предоставит эти методы. В Python для этого импортируют `ABC` и `abstractmethod` из модуля `abc` и помечают каждый метод декоратором `@abstractmethod`. Поэтому один список может хранить объекты нескольких подклассов.

**Связи между классами.** <Term id="b3-2-class-relationship"/> — это одна из трёх связей: `is_a` (наследование), `has_a` (один объект хранит ссылки на другие) или `part_of` (более сильная форма `has_a`). <Term id="b3-2-aggregation"/> — это связь `has_a`, в которой оба объекта могут существовать отдельно: плейлист хранит песни, которые существуют и после его удаления. <Term id="b3-2-composition"/> — это связь `part_of`, в которой части не могут существовать без целого: книга создаёт свои главы, которые исчезают вместе с ней. В UML наследование обозначается пустым треугольником у суперкласса, агрегация — пустым ромбом, а композиция — закрашенным ромбом на стороне целого. Кратность, например `1` или `0..*` у каждого конца, показывает, сколько объектов участвует в связи.

<Callout kind="tip">Спросите себя: могла бы часть существовать, если целое удалить? Если могла, связь — агрегация; если не могла, — композиция.</Callout>

**Паттерны проектирования.** Курс требует объяснить три паттерна.

<Callout kind="define">Паттерн проектирования — это проверенный многоразовый план для типовой задачи проектирования. Он показывает, как классы должны работать вместе, но не даёт готового кода.</Callout>

- <Term id="b3-2-singleton"/> оставляет ровно один экземпляр класса, общий для всей программы. Конструктор скрыт, а статический метод возвращает этот экземпляр.
- <Term id="b3-2-factory"/> даёт связанным продуктам один общий интерфейс. Фабрика выбирает, какой подкласс создать, поэтому новые виды можно добавлять, не меняя код, который использует интерфейс.
- <Term id="b3-2-observer"/> связывает издателя с подписчиками. Подписчики добавляют себя в список издателя или удаляют себя из него, а издатель уведомляет их, когда меняются его данные.

## Разбор примера

Транспортная компания хранит свои машины в одном списке. У каждой машины есть имя и максимальная дальность, у автомобилей есть признак электрического, а у кораблей — грузоподъёмность. Программа ниже использует наследование и полиморфизм, поэтому один цикл выводит движение каждой машины.

```python
class Vehicle:
    def __init__(self, name, max_range):
        self.name = name
        self.max_range = max_range

    def move(self):
        return self.name + " is moving"


class Car(Vehicle):
    def __init__(self, name, max_range, electric):
        super().__init__(name, max_range)
        self.electric = electric

    def move(self):
        return self.name + " is driving"


class Ship(Vehicle):
    def __init__(self, name, max_range, cargo):
        super().__init__(name, max_range)
        self.cargo = cargo

    def move(self):
        return self.name + " is sailing"


fleet = [Vehicle("Bus", 400), Car("Sedan", 500, True), Ship("Ferry", 800, 3000)]
for vehicle in fleet:
    print(vehicle.move())
print(fleet[1].electric)
print(fleet[2].max_range)
```

Программа выводит:

```text
Bus is moving
Sedan is driving
Ferry is sailing
True
800
```

## Типичные ошибки

<Callout kind="mistake">Ожидать, что для объекта подкласса выполнится версия суперкласса. Версия подкласса выполняется всегда, когда она переопределяет метод с тем же именем.</Callout>

<Callout kind="mistake">Написать конструктор подкласса без вызова `super().__init__()`, поэтому унаследованные атрибуты не получают значений.</Callout>

<Reveal title="Почему подкласс не может прочитать приватный атрибут суперкласса?">

В Python `self.__name` переименовывается внутри класса, который его записывает, поэтому подкласс ищет другое имя и получает ошибку. Читайте значение через публичный геттер, который предоставляет суперкласс, например `get_name()`.

</Reveal>

<Callout kind="mistake">Путать агрегацию с композицией, потому что обе — связи has_a. Спросите себя, может ли часть существовать после удаления целого.</Callout>

<Callout kind="mistake">Создавать объект абстрактного класса и ждать, что всё сработает. Python выдаст TypeError, и подкласс, который не реализует абстрактный метод, тоже нельзя создать.</Callout>

## Коротко

- Наследование позволяет подклассу использовать суперкласс, а `super()` запускает конструктор суперкласса.
- Полиморфизм позволяет одному вызову вести себя по-разному для разных объектов; переопределение даёт версию подкласса во время выполнения.
- Абстрактный класс объявляет методы без кода и не может быть создан; его подклассы обязаны реализовать эти методы.
- Утиная типизация проверяет, какие методы есть у объекта, а не его класс, и сообщает об отсутствующем методе только тогда, когда выполняется эта строка.
- Агрегация — это связь has_a с независимыми объектами; композиция — это связь part_of, в которой части не существуют без целого.
- Паттерны «одиночка», «фабрика» и «наблюдатель» — проверенные структуры для типовых задач проектирования.
