## Суть

Абстрактный тип данных (abstract data type, ADT) задаётся операциями, которые разрешено выполнять над его данными, а не способом хранения этих данных. Код, который использует ADT, может не меняться при смене реализации. Эта тема охватывает идею ADT, а затем связные списки, бинарные деревья поиска, множества и хеш-таблицы.

## Объяснение

### Абстрактные типы данных

Каждый <Term id="b4-1-adt"/> имеет интерфейс — набор операций, которые может выполнять пользователь. Очередь как ADT, например, предоставляет enqueue, dequeue, peek и isEmpty и больше ничего, поэтому её элементы нельзя отсортировать через неё.

Из этого следуют два принципа. Первый — <Term id="b4-1-abstraction"/>: пользователь работает с тем, что делает каждая операция, а не с тем, как она реализована. Второй — <Term id="b4-1-encapsulation"/>: к данным можно обратиться только через определённые операции, поэтому другой код не может нарушить структуру. Поскольку реализация скрыта, её можно заменить, не меняя программы, которые используют ADT. Хорошие первые примеры — стек и очередь: см. <Term id="b2-2-stack"/> и <Term id="b2-2-queue"/> в теме B2.2.

Большинство ADT использует операции, например <Term id="b4-1-insertion"/>, которая добавляет элемент, <Term id="b4-1-deletion"/>, которое удаляет его, и <Term id="b4-1-search"/>, который находит элемент, удовлетворяющий условию. Их стоимость зависит от ADT, а не только от названия операции.

### Связные списки

В основе лежит <Term id="b4-1-linked-list"/>: последовательность узлов. Каждый узел хранит значение и указатель на следующий узел. Первый узел называется головой, а в односвязном списке последний узел указывает на None. Добавление и удаление узла меняют только указатели, поэтому вставка в голову и удаление головы занимают время $O(1)$. Поиск элемента, а также добавление в конец без указателя на хвост занимают $O(n)$, потому что список приходится обходить по одному узлу.

По сравнению с массивом связный список легко меняет размер и дёшево меняется в середине. У него нет прямого доступа по индексу, а каждый узел хранит дополнительный указатель. Списки подходят для данных, размер которых часто меняется, а массивы — для данных, которые читаются по позиции.

Ещё один вариант — <Term id="b4-1-doubly-linked-list"/>: каждый узел хранит второй указатель, ведущий к предыдущему узлу. С ссылками на голову и хвост вставка и удаление с любого конца занимают $O(1)$ времени, а список можно обходить в обоих направлениях. Третий вариант — <Term id="b4-1-circular-linked-list"/>: последний узел указывает на голову, поэтому у списка нет конечного маркера. Он подходит для повторяющихся задач, например для планирования round-robin, но обход должен остановиться, когда вернётся к голове.

### Бинарные деревья поиска

Каждое <Term id="b4-1-bst"/> — это дерево из узлов с уникальными ключами, у каждого из которых не больше двух потомков. Ключи в левом поддереве узла меньше его ключа, а ключи в правом поддереве больше. Вставка идёт по тому же пути, что и поиск. Если дерево сбалансировано, поиск занимает $O(\log n)$ времени, потому что каждое сравнение отбрасывает примерно половину оставшихся узлов. Если ключи приходят в отсортированном порядке, дерево превращается в цепочку, и поиск занимает $O(n)$ времени.

### Множества

Каждое <Term id="b4-1-set"/> хранит различные элементы без определённого порядка, поэтому добавление уже имеющегося элемента ничего не меняет. Его операции: добавление, удаление, проверка принадлежности, объединение, пересечение и разность. Множества часто строят на хеш-таблицах, поэтому проверка принадлежности и добавление занимают в среднем $O(1)$ времени. В Python `set` — это встроенный тип.

### Хеш-таблицы и основные принципы

Каждая <Term id="b4-1-hash-table"/> хранит пары «ключ–значение». Хеш-функция превращает каждый ключ в индекс, поэтому поиск, вставка и удаление занимают в среднем $O(1)$ времени. Хорошая хеш-функция детерминирована, равномерно распределяет ключи и быстро вычисляется. Когда два ключа дают один индекс, возникает коллизия. Её можно разрешить методом цепочек (separate chaining), где каждая ячейка хранит список записей, или открытой адресацией (open addressing), которая ищет другой свободный слот.

Коэффициент заполнения, обозначаемый $\lambda$, — это число записей, делённое на число ячеек (buckets). Высокий коэффициент означает больше коллизий и более медленные операции, поэтому таблицу часто перестраивают, когда $\lambda$ превышает порог, например 0,7, и заново хешируют все записи.

## Разбор примера

Музыкальное приложение хранит плейлист как двусвязный список, чтобы пользователь мог двигаться вперёд и назад. Программа ниже добавляет три песни и выводит плейлист в обоих направлениях. Предскажите обе строки до запуска программы.

```python
# Каждая песня знает предыдущую и следующую песню.
class Song:
    def __init__(self, title):
        self.title = title
        self.prev = None
        self.next = None


class Playlist:
    def __init__(self):
        self.head = None
        self.tail = None

    def add_song(self, title):
        song = Song(title)
        if self.head is None:
            self.head = song
            self.tail = song
        else:
            self.tail.next = song
            song.prev = self.tail
            self.tail = song

    def forwards(self):
        titles = []
        current = self.head
        while current is not None:
            titles.append(current.title)
            current = current.next
        return titles

    def backwards(self):
        titles = []
        current = self.tail
        while current is not None:
            titles.append(current.title)
            current = current.prev
        return titles


playlist = Playlist()
playlist.add_song("Intro")
playlist.add_song("Night")
playlist.add_song("Outro")
print(playlist.forwards())
print(playlist.backwards())
```

<Steps>
  <Step>Первая песня становится и головой, и хвостом, потому что плейлист пуст.</Step>
  <Step>Каждая следующая песня связывается за хвостом, и затем хвост переходит к ней. Задаются указатель next старого хвоста и указатель prev новой песни.</Step>
  <Step>forwards идёт от головы по указателям next, а backwards — от хвоста по указателям prev. Два списка содержат одни и те же названия в противоположном порядке.</Step>
</Steps>

Вывод: ['Intro', 'Night', 'Outro'] в первой строке и ['Outro', 'Night', 'Intro'] во второй.

## Типичные ошибки

- Не считай ADT одной конкретной программой. ADT задаётся операциями, а реализовать его может и массив, и связный список.
- Не используй `while current is not None` для циклического списка: цикл никогда не закончится. Остановись, когда обход вернётся к голове.
- Не меняй только удаляемый узел. Узел перед ним должен указывать на узел после удалённого.
- Не считай бинарное дерево поиска всегда быстрым. Отсортированные вставки дают цепочку, и поиск тогда занимает $O(n)$ времени.

## Коротко

- ADT задаётся операциями, и его реализацию можно менять, не затрагивая код, который его использует.
- Вставка и удаление в голове связного списка занимают $O(1)$ времени, а доступ и поиск — $O(n)$.
- Сбалансированное бинарное дерево поиска ищет за $O(\log n)$ времени, а цепочка из отсортированных ключей — за $O(n)$.
- Множество хранит различные элементы без порядка. Хеш-таблица даёт поиск за $O(1)$ в среднем, а коэффициент заполнения определяет, когда её перестраивать.
