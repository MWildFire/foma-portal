## Суть

Переменные существуют только во время работы программы, а файл сохраняет данные и после её завершения. Файл читается и записывается строго по порядку, поэтому режим открытия, способ перемещения по файлу и момент закрытия определяют, сохранятся данные, потеряются или прочитаются правильно. Во многих заданиях от вас требуют предсказать, что выведет короткая программа для работы с файлом, поэтому проследите её по строкам.

## Объяснение

### Зачем хранить данные в файле

Данные, записанные в файл, сохраняются после завершения программы, поэтому школы, банки и информационные системы хранят записи в файлах. <Term id="b2-5-text-file"/> хранит обычные символы, и каждая строка обычно содержит одну <Term id="b2-5-record"/>, например имя и результат, разделённые запятой. Программа должна разбить строку на элементы, прежде чем их использовать, а число, записанное как текст, нужно перевести функцией int() перед любыми вычислениями.

Каждая программа, которая работает с файлом, выполняет одни и те же <Term id="b2-5-file-processing-operation"/> по порядку:

<Steps>
  <Step>Откройте файл в режиме: «r» для чтения, «w» для записи или «a» для добавления.</Step>
  <Step>Читайте или записывайте записи одну за другой.</Step>
  <Step>Закройте файл, чтобы данные, которые ещё хранятся в памяти, были сохранены, а файл освободился.</Step>
</Steps>

### Последовательные файлы

<Term id="b2-5-sequential-file"/> хранит записи одну за другой. На рисунке 17 (стр. 407) записи с 1 по 5 идут от начала файла до <Term id="b2-5-end-of-file"/>. Чтобы получить запись, программа начинает с начала и читает, пока не дойдёт до нужной. Это и есть <Term id="b2-5-sequential-access"/>, поэтому запись нельзя пропустить.

Последовательные файлы плохо подходят для быстрого поиска одной записи, но у них низкие накладные расходы: им нужно мало дополнительной структуры и места. Учебник приводит в пример системные журналы, пакетную обработку и архивы (стр. 407). Журнал добавляет каждое новое событие в конец, банк за ночь обрабатывает записи за день одним проходом, а к архиву почти не обращаются.

### Режим записи и режим добавления

Открытие файла в <Term id="b2-5-write-mode"/> («w») стирает прежнее содержимое, поэтому всё, что записано дальше, становится всем файлом. Открытие в <Term id="b2-5-append-mode"/> («a») сохраняет прежнее содержимое, а новые данные пишутся после него. Оба режима для Python учебник показывает на странице 411.

<Callout kind="mistake">Режим записи стирает файл сразу при открытии, ещё до того как записана хотя бы одна строка. Если нужно только дописать строку, используйте режим добавления.</Callout>

### Чтение построчно

Файл, открытый в <Term id="b2-5-read-mode"/> («r»), отдаёт программе текст, не меняя его. Метод readline() возвращает следующую строку вместе с переводом строки. Когда строки закончились, он возвращает пустую строку «», поэтому цикл while, который останавливается на «», прочитает файл ровно один раз. Цикл for по объекту файла делает то же самое.

### Запись и добавление в Python

Метод write(text) записывает одну строку. Метод writelines(list) записывает подряд все строки из списка и не добавляет переводов строк, поэтому, если каждая запись должна занимать свою строку, перевод строки добавьте сами.

### Симулированные файлы в портале

Код портала не работает с настоящими файлами, поэтому в примерах используется io.StringIO. StringIO хранит текст в памяти и ведёт себя как файл: у него есть позиция, которая смещается при чтении и записи. Новый StringIO() пуст, как файл, открытый в режиме записи. StringIO, созданный с текстом, ставит позицию в начало, поэтому запись перезаписывает символы там; чтобы дописать в конец, сначала вызовите seek(0, io.SEEK_END). Настоящий файл, открытый в режиме «r+», ведёт себя так же, поэтому подпись «чтение» у этого режима в учебнике может вводить в заблуждение.

<Callout kind="tip">Читайте программу так, будто каждый StringIO — это файл на диске. Задайте себе два вопроса: где стоит позиция в начале программы и что меняет каждая запись?</Callout>

### Закрытие файлов

<Term id="b2-5-close-file"/> завершает работу программы с файлом. Учебник отмечает, что закрытие предотвращает ошибки из-за незакрытых ресурсов (стр. 407). Блок with закрывает файл по окончании, даже после ошибки, поэтому вызов close() в примере учебника на странице 412 безвреден, но не нужен.

## Разбор примера

Программа ниже записывает две строки в режиме записи, добавляет третью строку и затем читает файл построчно. Предскажите каждую строку вывода, прежде чем запускать код.

```python
import io

# Each StringIO stands in for a file on disk, so no real file is created.

# Write mode ("w"): a new, empty file. Writing starts from nothing.
disk = io.StringIO()
disk.writelines(["Mon,rain\n", "Tue,sun\n"])
text = disk.getvalue()
disk.close()

# Append mode ("a"): the old text is kept and the write position moves to the end.
disk = io.StringIO(text)
disk.seek(0, io.SEEK_END)
disk.write("Wed,cloud\n")

# Read mode: read the file line by line until the end of the file.
disk.seek(0)
line = disk.readline()
count = 0
while line != "":
    count = count + 1
    print(count, line.rstrip("\n"))
    line = disk.readline()
disk.close()
```

Вывод:

```text
1 Mon,rain
2 Tue,sun
3 Wed,cloud
```

Шаг записи создаёт первые две строки с нуля. Шаг добавления переводит позицию записи в конец, поэтому третья строка добавляется после двух первых. Цикл останавливается, когда readline() возвращает пустую строку, то есть после третьей строки.

## Типичные ошибки

<Callout kind="mistake">Сравнение readline() с None, как в Java, в Python не останавливает цикл: в конце файла возвращается пустая строка, а не None. Сравнивайте с «» или используйте цикл for.</Callout>

<Callout kind="mistake">writelines() не добавляет переводов строк. Список ["red", "green"], записанный через writelines(), даёт redgreen в одной строке, а не две строки.</Callout>

<Callout kind="mistake">Число, прочитанное из файла, — это текст. "12" + "9" даст "129", а не 21. Сначала переведите текст в число функцией int().</Callout>

<Callout kind="mistake">Запись в StringIO, в котором уже есть текст, без перехода в конец перезаписывает его первые символы. Настоящий файл, открытый в режиме «r+», ведёт себя так же.</Callout>

- Последовательный файл хранит записи одну за другой и читается по порядку, с начала.
