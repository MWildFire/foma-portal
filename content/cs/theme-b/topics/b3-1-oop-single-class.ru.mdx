## Суть

Объектно-ориентированное программирование (ООП) объединяет данные об одном виде объектов и действия, которые работают с этими данными. План такого вида — это <Term id="b3-1-class"/>, а каждый реальный предмет, созданный по этому плану, — это <Term id="b3-1-object"/>. В теме рассматривается, как спроектировать один класс, записать его на Python и защитить его данные.

## Объяснение

**Классы и атрибуты.** Класс — это чертёж. Он задаёт <Term id="b3-1-attribute"/> каждого объекта и <Term id="b3-1-method"/>, которые объект может выполнять. Сам по себе класс описывает вид предметов, но не хранит значения конкретного предмета. Поэтому проектирование класса начинается с двух вопросов: что должен помнить каждый объект и что он должен уметь делать.

**Объекты и конструкторы.** Создание объекта называется <Term id="b3-1-instantiation"/>. В Python его выполняют, вызывая имя класса с начальными значениями, например `Film("Heat", 170)`. При этом запускается <Term id="b3-1-constructor"/> — специальный метод с именем `__init__`, первый параметр которого всегда `self`. Строка `self.__title = title` внутри него записывает значение в атрибут нового объекта. Каждый объект получает собственные атрибуты, поэтому объекты одного класса могут хранить разные значения.

**Методы и статические элементы.** Атрибут хранит данные, а метод — это функция внутри класса, которая использует или меняет эти данные. Методы вызываются через точку, например `first.get_title()`. Некоторые значения, например счётчик созданных объектов, принадлежат всему классу и читаются через имя класса. В Python такое значение называют классовой переменной, а общее название этой идеи — <Term id="b3-1-static"/>. Классовую переменную записывают в теле класса перед `__init__` и читают так: `Film.count`. Нестатический атрибут задаётся через `self` в конструкторе и принадлежит только одному объекту.

**Скрытие данных.** <Term id="b3-1-encapsulation"/> — это принцип скрытия данных внутри класса: внешний код получает к ним доступ только через публичные методы. Это даёт три выгоды: данные остаются в безопасности, изменения внутри класса не ломают код снаружи, а класс можно повторно использовать в других программах. Сокрытие информации (information hiding) преследует ту же цель.

**Уровни доступа.** Видимость задаёт <Term id="b3-1-access-modifier"/>. Есть три модификатора: private (только внутри класса), protected (класс и его подклассы) и public (любой класс). В Python два символа подчёркивания перед именем делают атрибут приватным, например `self.__balance`. Один символ подчёркивания — это договорённость для protected, а имя без префикса публично. Python не запрещает доступ к приватным именам так строго, как Java: переименованное имя защищает от случайного доступа, но не от намеренного. Поэтому приватный атрибут обычно читают через публичный геттер, например `get_balance()`, а меняют через сеттер, который сначала проверяет новое значение.

**UML-диаграммы классов.** <Term id="b3-1-uml-class-diagram"/> показывает класс другим разработчикам без кода. Диаграмма состоит из трёх разделов: имени класса, атрибутов и методов. Каждая строка начинается со знака видимости: минус для private, плюс для public и решётка для protected. Атрибут записывается как `имя: тип`, а метод — как `имя(параметры): тип возвращаемого значения`. Линии между классами показывают связи: агрегацию (незакрашенный ромб), композицию (закрашенный ромб) и наследование (незакрашенный треугольник), которые разбираются в B3.2.

<Callout kind="define">В этой теме атрибут и переменная экземпляра означают одно и то же.</Callout>

<Callout kind="tip">Прежде чем писать код, выпиши существительные из условия как возможные атрибуты, а глаголы — как возможные методы. Потом убери всё, что программе не нужно.</Callout>

## Разбор примера

Задача: приложение кинотеатра хранит фильмы. У каждого `Film` есть приватное название и приватная продолжительность в минутах. В классе также есть статический счётчик созданных фильмов, публичный метод `get_title()` и публичный метод `is_long()`, который возвращает True, если фильм длится больше 150 минут.

```python
class Film:
    # Статический атрибут: один общий счётчик для всех объектов Film
    count = 0

    def __init__(self, title, minutes):
        self.__title = title
        self.__minutes = minutes
        Film.count = Film.count + 1

    def get_title(self):
        return self.__title

    def is_long(self):
        return self.__minutes > 150


first = Film("Heat", 170)
second = Film("Notes", 95)
print(first.get_title(), first.is_long())
print(second.is_long(), Film.count)
```

Программа выводит:

```text
Heat True
False 2
```

## Типичные ошибки

<Callout kind="mistake">Ты записываешь атрибут как обычную локальную переменную, например title = title, в конструкторе. Такое значение исчезает, когда конструктор заканчивает работу; сохрани его через self.</Callout>

<Callout kind="mistake">Ты думаешь, что статическая переменная копируется в каждый объект. На самом деле копия одна. Читай её через имя класса, Film.count, а не через объект.</Callout>

<Reveal title="Почему строка acc.__balance = 500 не меняет баланс?">

Внутри класса Python переименовывает `self.__balance`. Вне класса строка `acc.__balance = 500` создаёт новый атрибут, поэтому приватное значение остаётся прежним. Меняй приватные данные через сеттер, который проверяет новое значение.

</Reveal>

<Callout kind="mistake">Ты ставишь плюс перед приватным атрибутом в UML-диаграмме. Используй минус для private, плюс для public и решётку для protected.</Callout>

## Коротко

- Класс — это чертёж, а объект создаётся из него через создание экземпляра и конструктор.
- Атрибуты хранят данные каждого объекта, методы задают то, что делает объект.
- Статическая переменная или метод принадлежит классу и используется через имя класса.
- Инкапсуляция скрывает данные за публичными методами; в Python двойное подчёркивание делает атрибут приватным.
- UML-диаграмма классов показывает имя класса, атрибуты и методы, у каждого из которых есть знак видимости.
